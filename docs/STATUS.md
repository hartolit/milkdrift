# Status

This document owns current implementation facts and limitations.

## Implemented

- A Rust 1.95.0, edition-2024 workspace with twenty safe-Rust packages and a curated lint/dependency policy.
- `milkdrift-daemon` is the authoritative local host. One dedicated thread owns synchronous redb, artifact, runtime, control, registry-query, layout, and durable external-command-ledger access behind a bounded `sync_channel`; Axum reactor tasks receive overload instead of blocking or growing an unbounded queue. The daemon opens runtime admission closed, performs targeted active-run recovery, registers the workflow-control adapter plus configured process/model profiles, starts fixed bounded effect workers, then becomes ready. A configured maintenance notification interval drives scheduler/effect progress without a busy loop.
- Daemon configuration schema 2 covers a loopback bind, owned data root, file/environment secret references, credential-to-actor/grant bindings, explicit workflow/run/capability/filesystem/network/secret scopes and numeric ceilings, fixed scheduler/effect/request bounds, process/model profile sources, explicit peer relationships, command-ledger retention, and drain/cancel/retain shutdown policy. Wildcard, unknown-side-effect, omitted-operation, infinite-validity, or unbounded grants require the visually explicit `dangerous_allow_broad_authority` acknowledgement; safe configurations fail closed. Schema 1 is rejected rather than silently widened. Validation and path normalization happen before storage opens. Non-loopback plaintext, missing credentials, permissive file permissions, unknown fields, invalid versions, and invalid bounds fail closed. Redacted effective configuration never includes resolved values.
- Local HTTP authentication is mandatory. Credential references are reread on use for rotation, file credentials require private permissions on Unix, digest comparison is constant-time, and actor/grant/revocation/preset facts come only from server configuration. Authority evaluation remains the separate ordinary immutable-grant path. CORS is disabled and Authorization, environment, prompts, outputs, artifacts, and resolved secrets are excluded from public diagnostics and default tracing.
- `milkdrift-control-protocol` is a pure protocol-1.0 package with duplicate-safe bounded JSON, explicit negotiation, stable error/result envelopes, actor-free idempotent command requests, page/feed-bound opaque cursor schema 1, immutable revision/diff models, compact run/node/attempt/proposal models, projected timeline categories, capability/authority/artifact/health reads, and external SSE observations. Internal events, redb keys, snapshots, provider objects, process handles, and framework types are not wire contracts.
- Layout document schema 1 stores only exact workflow/revision association, bounded node presentation, groups/annotations, viewport, author, generation, and an independent digest. It is persisted outside immutable semantic revisions with optimistic generation checks; changing it cannot change semantic revision identity.
- The control API exposes authenticated version negotiation, liveness/readiness, one idempotent command endpoint, bounded revisions/diffs, runs/nodes/attempts/timelines, proposal status, capabilities, current authority, artifact metadata/ranges, layouts, run SSE, and daemon-health SSE. Run stream cursors are monotonic and feed-bound; heartbeats are transport-only, current authorization is rechecked, reconnect resumes after the exact observed cursor, and shutdown/rotation produces an external closing or resync observation.
- `milkdrift-control-client` owns the complete HTTP mapping, negotiation, redacted bearer handling, typed page/query/command methods, bounded safe-query retry classification, explicit artifact ranges, and resumable SSE parsing. Mutating calls are never implicitly retried. `milkdrift-cli` is a storage-free thin client covering daemon, blueprint, run, node, attempt, proposal, capability, peer, artifact, and layout operations with human output, stable JSON schema 1, confirmations, explicit download destinations, reconnect status, and stable exit categories.
- `milkdrift-peer-protocol` is a transport-neutral protocol-1.0 package with duplicate-safe bounded envelopes, explicit version negotiation, authenticated session cross-checks, expiring digest-bound catalog snapshots, exact invocation/delegation/acceptance contracts, monotonic resumable observation pages, separate cancellation acknowledgements, and metadata-first bounded artifact transfer. It has no Tokio, Axum, Reqwest, redb, provider, process, or UI dependency.
- `milkdrift-peer-http` provides the distinct `/peer/v1` realm, Rustls HTTPS client, explicit loopback-development exception, request-time rotating bearer authentication mapped to configured `PeerId`, default-deny relationship authority, capability/operation filters, request-rate/concurrency/duration/cost/observation/artifact quotas, graceful drain/revocation, and bounded redacted HTTP behavior. Operator URLs are fixed configuration and redirects are disabled.
- Serving peers derive scoped catalogs from live capability-host generations. Consuming peers verify catalog digest/expiry and register collision-resistant ordinary remote adapters with exact typed peer/catalog/capability provenance, `Locality::Peer`, and configured trust zones. Replacement, disconnect, drain, revocation, and expiry stop new resolution without making catalogs durable workflow truth; the runtime still records one exact ordinary resolved snapshot.
- Remote direct-adapter execution durably syncs acceptance before response, rejects same-key/different-request conflicts, persists contiguous observations, resumes by exclusive sequence cursor, and keeps cancellation acknowledgement separate from connection state. Accepted-before-entry restart recovery may enter once; a crash after durable adapter-entry intent is never re-entered and closes as explicit outcome uncertainty. Local re-dispatch derives the same peer request identity, so response loss or local restart cannot create replacement work.
- Peer artifact staging exchanges exact digest/size/media type and authority metadata before raw bytes, uses sequential chunks or bounded ranges, resumes owned temporary uploads, verifies content before digest-derived atomic publication, and deduplicates only verified published content. Aborts and mismatches hide/remove incomplete content; secret/config media types, arbitrary paths, and over-quota transfers are rejected.
- Blueprint task configuration schema v2 owns an immutable context policy with direct-input, graph-depth, exact-node, semantic-role, category, artifact-metadata, budget, ordering/truncation, fresh/continuation, and fail-closed semantics. Blueprint revision and mutation readers deliberately refuse v1 because inventing a policy would change semantic identity; canonical v2 fixtures bind the new digest.
- `milkdrift-model` owns provider-neutral schema-v1 context-manifest, model-task, and model-response documents. Manifests bind exact run/revision/node/execution/attempt and policy facts, ordered references/evidence, selected sizes and sensitivity/authority, reasons/omissions, totals/budget, and a verified domain-separated digest. Model tasks support ordered system/developer/user/assistant/tool-result messages, text and typed artifact/image/file references, tools, structured output, explicit sessions, typed reasoning, bounded extensions, streaming intent, and output caps; responses preserve text, structured data, tool calls as data, finish reasons, usage/cost evidence, and provider metadata.
- `milkdrift-runtime::context` is a pure causal selector. It traverses only explicit incoming control/data edges to a bounded depth, applies exact selectors and visible-scope isolation, considers artifact metadata before bytes, orders by causal depth/kind/node/canonical source, checks budgets incrementally, and records stable omissions. Required missing, denied, or over-budget evidence fails before dispatch. Its publication helper commits the canonical restricted manifest artifact with a digest-derived idempotent identity before provider entry and survives redb restart.
- Invocation-request schema v2 has one explicit typed context-manifest artifact reference. The reader accepts context-free v1 requests only through the unambiguous compatibility path and writers always emit v2. The host store data port reads exact verified artifacts; model invocations additionally verify manifest media, digest, and exact attempt provenance.
- `milkdrift-model-provider` implements a live `model.generate` adapter with non-secret endpoint-profile schema v1, explicit profile revision/model alias/protocol/auth refs/limits/redirect/TLS/proxy/host/trust/features/options, bounded reqwest/rustls transport, strict SSE parsing, feature negotiation before entry, scoped secret resolution, cooperative cancellation, and committed output artifacts. A Fresh request verifies the exact manifest against its attempt and sends the same canonical bytes as the first system context block; encoded request bodies have an explicit profile bound. Remote endpoints require HTTPS; plaintext is loopback-development-only; credentials/query/fragment URLs, compressed responses, ambient proxies by default, and cross-origin redirects are rejected.
- The OpenAI-compatible mapping supports text/system/developer/tool-result messages, image data references, tools, JSON-schema output, mapped reasoning effort, non-streaming chat responses, streaming text/tool fragments, usage/cached usage, finish reasons, and bounded `org.milkdrift.openai/request` options. The native Anthropic mapping independently handles system blocks, user/assistant/tool-result content, images, tool definitions/calls, Messages API events, usage/finish reasons, required version/auth headers, and bounded `org.milkdrift.anthropic/request` options. Anthropic structured output/developer role/reasoning controls and generic file parts are rejected; explicit continuation and provider-managed sessions are rejected for both until an exact protocol mapping exists.
- Model response, final text, structured output, tool-call data, and bounded provider metadata have separate artifact media contracts and are all committed before output/success reports. A publication failure yields failure, no prompt or response is logged, restricted publication is the production default, and cancellation acknowledgement does not claim provider-side termination.
- `milkdrift-authority` owns canonical `ActorRef`, `PeerId`, immutable schema-v1 grant revisions and digests, typed command/control operations, workflow/run/capability/filesystem/network/secret scopes, locality/peer/trust envelopes, validity and revocation facts, cost/duration/invocation/artifact/unit/concurrency ceilings, pure deterministic evaluation, schema-v1 decision snapshots and digests, immutable execution-authority bases, adapter execution requirements, and redacted opaque secret mechanics. `AuthorRef` remains distinct revision provenance.
- External runtime commands present an exact grant revision, digest, and revocation generation to an injected evaluator. The unchanged command-v1 bytes are wrapped by authorization-audit schema v1; a decision-bearing command-result schema v2 is committed atomically with accepted or denied results. Exact duplicate command IDs return the original decision/result without reevaluation. Starting a run commits its immutable actor/grant/policy/workflow/run/revision/decision basis before `RunStarted`; structured child runs inherit it. Internal system transitions and worker reports use private runtime-owned paths and are rejected by the external command API.
- Start and revision-adoption planning recursively validate reachable task, reducer, repeat, and subworkflow capability envelopes against the frozen run basis without depending on live availability. An out-of-envelope requirement is a typed durable command denial, so draft creation or proposal storage cannot grant execution authority. An AI controller follows the same path and cannot enlarge its own grant.
- `milkdrift-control` owns strict schema-v1 control commands and workflow proposals for human, service, process, and model producers. Proposal JSON is byte/depth/item/string bounded, duplicate-key-safe, unknown-field rejecting, canonical, domain-separated digest-bound, and optimistic against exact base revision/digest plus optional live run sequence. It carries closed mutation batches, exact provenance, bounded rationale/risk/assumption lists, evidence and artifact references, application policy, an optional run action, and an untrusted stop claim. Oversized reasoning must remain in an artifact. The model bridge reads structured output only; prose and tool calls are ignored as control intent.
- `ControlService` privately constructs and validates prospective revisions, checks the exact capability/profile/trust/side-effect/budget delta against the caller's ordinary grant, classifies deterministic policy-v1 risk, stores immutable revisions, and uses existing authorized runtime commands for live reconciliation, approval, apply, pause/resume/cancel/retry, signal, create, and start. Low-risk auto-apply is limited to future pure/read-only additions with exact apply authority. Existing/started work, dependencies touching started descendants, terminal changes, side effects, provider/profile/trust expansion, subworkflow/interface changes, cancel/resume/signal, and uncertainty-sensitive work require approval or stronger action authority. Stable derived runtime command and reconciliation identities preserve idempotent replay; stale base/sequence/digest/plan guards fail closed.
- Observer, Advisor, Supervisor, Controller, and Autonomous control presets expand into normal immutable `AuthorityGrant` revisions with the exact caller-supplied run/workflow, capability, budget, validity, and revocation scope. The in-process `milkdrift-workflow-control` capability advertises inspect/propose/pause/resume/apply/retry/signal operations and resolves caller authority through a trusted opaque context reference outside model-owned data. Malformed or adversarial inputs report a normal rejected terminal with no side effect. A bounded controller blueprint builder emits an ordinary acyclic wrapper containing one explicit pinned `Repeat` with hard limits and a human checkpoint.
- Authorization-filtered control read models expose current run lifecycle/revision/digest/usage, node states, latest attempt anchors, exact resolved capability and provider profile snapshots, context-manifest and output/artifact references, side-effect/idempotency facts, terminal failures, late evidence, uncertainty obligations, current reconciliation state, immutable revision lineage, proposal status, and stable-cursor raw event timeline pages. Settled high-frequency detail remains journal history by design.
- `milkdrift-capability-host` owns a bounded live registry and narrow concrete-adapter interface. Registrations are keyed by capability identity plus nonzero descriptor revision; identical duplicates are idempotent, conflicting reuse is rejected, newer revisions become current, and old exact generations remain dispatchable until explicitly drained and reaped. Resolution uses one locked snapshot and canonical authority evaluation of every exact descriptor candidate before fresh availability or capacity evidence, followed by explicit priority and stable identity/revision ordering. Placement filters distinguish local and typed peer identities; an unavailable allowed generation never causes fallback to a disallowed locality or peer.
- Live host admission has no hidden queue. The runtime durably records the authorized resolution before lease dispatch, reevaluates the exact stored generation at claim, and reevaluates again immediately before adapter code. Process, model, workflow-control, and peer adapters declare their filesystem/network/secret/budget requirements through the same host contract and receive the frozen basis plus resolution/final-entry decisions in their execution context. Typed revocation or narrowing denial releases the lease and never calls adapter code. Once adapter entry occurred, later revocation cannot invent a different terminal outcome. Exact-generation permit ownership, cancellation routing, panic containment, drain/reap behavior, and bounded registry queries remain unchanged.
- `SecretResolver` returns non-serializable, non-clone sensitive values with redacted formatting and zero-on-drop storage. Deterministic in-memory test infrastructure remains, and `milkdrift-secret-env` adds the first concrete source: an explicit opaque-reference-to-environment-name map that never enumerates the environment or serializes/retains resolved values.
- `milkdrift-local-process` owns private-invariant process-profile document schema v1. Profiles pin stable profile/capability/descriptor revisions; one namespaced operation; honest side-effect, idempotency, cancellation, restart, and platform facts; one absolute executable; fixed argv templates with explicitly named scalar/path/config/root/invocation/key substitutions; isolated working-directory mode; canonical access roots; selected input paths; cleared/allowlisted environment; secret refs; bounded stdin, stdout, stderr, timeouts, termination deadlines, children observations, input/output counts and bytes, declared regular-file outputs, and bounded namespaced extensions. Profiles contain no shell command and no secret value.
- The local-process adapter validates the exact pinned generation, materializes before resolving only required secrets, canonicalizes executable/workspace roots, starts with `env_clear`, and spawns one `Command` argument vector without a shell. Substitutions cannot add argv entries; missing/unknown inputs, NUL, excessive argv, invalid roots, and non-scalar text substitutions reject before process entry. Secret-bearing profiles cannot stream raw process text; exact secret bytes are redacted from bounded captures before publication.
- `milkdrift-capability-host::materialization` is the narrow host-owned workspace/artifact port. Its production `RuntimeStore` bridge reads exact workspace versions and verified bounded artifact chunks under explicit read authority, creates private temporary workspaces, copies only selected values, and imports only declared regular files or bounded captures through the content-addressed `ArtifactStore`. Relative normal paths, depth/count/byte limits, canonical containment, symlink/hardlink/special-file rejection, stable publication identity, run accounting, restricted sensitivity, invocation producer, exact input causes, and execution provenance are enforced. Incomplete publication streams are aborted; undeclared files remain temporary and are removed with the workspace.
- Process stdout and stderr are drained concurrently through a bounded synchronous channel before wait completion. Capture memory has independent hard bounds; overflow either drains/discards excess or terminates according to the profile. Progress/output/heartbeat counts are validated against the runtime's 1,024-observation bound. Exit code, signal, timeout, output overflow, cancellation, missing output, import failure, and unproven termination map to bounded typed terminal evidence.
- On Unix the child enters a new process group. Graceful/forced signals target the group, the immediate child is reaped, and confirmed cancellation requires observed group disappearance. Surviving descendants after immediate-child success are terminated and reported as a contract failure. Deliberate descendant group/session escape is not prevented and is advertised as unsupported. Non-Unix builds advertise no owned group or terminal group observation; cancellation can remain uncertain rather than claiming descendant cleanup.

It stops polling admission before shutdown, never holds the runtime claim gate during external work, and joins all threads on clean shutdown. Forced adapter removal returns exact unresolved invocation owners; retained or lost durable starts remain for runtime recovery.

Redb journal/artifact/admin/store responsibilities remain split behind narrow facades; integration and contract tests are grouped by behavior.

## Limitations

Peer support has no discovery, NAT traversal, VPN/overlay routing, hosted coordinator, automatic certificate authority, mutual-TLS identity mapper, shared database/workflow truth, distributed consensus, model synchronization, tensor transfer, browser client, or Iced desktop application. The daemon continues to bind its own listener only on loopback; public/LAN deployment requires operator-managed HTTPS reverse proxy or private connectivity. Bearer authentication is implemented, while mTLS termination is external. Catalog connection/reload is explicit rather than a continuously reconnecting discovery loop. Peer artifact transport is verified and separately staged, but automatic import/export between peer staging and every runtime artifact reference is not yet claimed. File-backed credential values rotate at request time; relationship identity, allowlist, quota, and durable revocation-generation configuration changes require restart. Production internet hardening beyond the documented Rustls client, fixed endpoints, bounds, rate/concurrency controls, and loopback two-daemon tests is not claimed.

The daemon has no dynamic adapter/profile/grant reload lifecycle beyond explicit peer catalog reload; there is no public local artifact upload/publication API, global event firehose, generalized plugin framework, optimized lifetime historical inspector index, or daemon-owned continuous controller lifecycle. Proposal list discovery is bounded by the daemon's durable external-command ledger while exact proposal truth is still queried through `milkdrift-control`; complete proposals remain immutable documents/artifacts rather than a new mutable repository. Context candidate acquisition remains a pure bounded runtime request, and context manifests are exposed through retained attempt/artifact references rather than a separate search service. The provider adapter currently maps OpenAI chat completions rather than the separate Responses API, has no discovery or pricing calculation, does not map generic file parts or provider-managed sessions, and uses a conservative whole-request cap equal to the smaller request/idle timeout because the blocking HTTP stack exposes no separate per-read timer. Cooperative cancellation closes at the next read/timeout boundary and cannot prove remote termination. Partial streamed fragments are durable observations, but no successful partial-response artifact is claimed after malformed/truncated/uncertain completion.

Local-process profiles provide mediation and ownership, not a sandbox: they do not enforce network isolation, CPU/memory quotas, a maximum child count, or prevention of a malicious Unix descendant creating a new session/process group. Regular-file input/output materialization is implemented; directory artifacts, sparse/special files, writable shared repository mounts, and a complete openat-style directory-handle implementation are not claimed. On non-Unix targets complete process-tree cancellation is not claimed. PID receipts are diagnostics only and are never used to reconnect after restart. Active projection memory is bounded by live semantic state, not universally constant: workflow size, active branches, unresolved/retained effects, output/context/artifact retention, configured workspace limits, and bounded worker ownership remain legitimate growth dimensions. Storage migration and automatic derived-index repair are not implemented; pre-release users must create a new store after incompatible format changes. The daemon control/layout/idempotency sidecar is atomically synced and single-owner but is a separate schema-1 file rather than a redb table; no migration or repair is claimed.
