# Status

This document owns current implementation facts and limitations.

## Implemented

- A Rust 1.95.0, edition-2024 workspace with fourteen safe-Rust packages and a curated lint/dependency policy.
- Blueprint task configuration schema v2 owns an immutable context policy with direct-input, graph-depth, exact-node, semantic-role, category, artifact-metadata, budget, ordering/truncation, fresh/continuation, and fail-closed semantics. Blueprint revision and mutation readers deliberately refuse v1 because inventing a policy would change semantic identity; canonical v2 fixtures bind the new digest.
- `milkdrift-model` owns provider-neutral schema-v1 context-manifest, model-task, and model-response documents. Manifests bind exact run/revision/node/execution/attempt and policy facts, ordered references/evidence, selected sizes and sensitivity/authority, reasons/omissions, totals/budget, and a verified domain-separated digest. Model tasks support ordered system/developer/user/assistant/tool-result messages, text and typed artifact/image/file references, tools, structured output, explicit sessions, typed reasoning, bounded extensions, streaming intent, and output caps; responses preserve text, structured data, tool calls as data, finish reasons, usage/cost evidence, and provider metadata.
- `milkdrift-runtime::context` is a pure causal selector. It traverses only explicit incoming control/data edges to a bounded depth, applies exact selectors and visible-scope isolation, considers artifact metadata before bytes, orders by causal depth/kind/node/canonical source, checks budgets incrementally, and records stable omissions. Required missing, denied, or over-budget evidence fails before dispatch. Its publication helper commits the canonical restricted manifest artifact with a digest-derived idempotent identity before provider entry and survives redb restart.
- Invocation-request schema v2 has one explicit typed context-manifest artifact reference. The reader accepts context-free v1 requests only through the unambiguous compatibility path and writers always emit v2. The host store data port reads exact verified artifacts; model invocations additionally verify manifest media, digest, and exact attempt provenance.
- `milkdrift-model-provider` implements a live `model.generate` adapter with non-secret endpoint-profile schema v1, explicit profile revision/model alias/protocol/auth refs/limits/redirect/TLS/proxy/host/trust/features/options, bounded reqwest/rustls transport, strict SSE parsing, feature negotiation before entry, scoped secret resolution, cooperative cancellation, and committed output artifacts. A Fresh request verifies the exact manifest against its attempt and sends the same canonical bytes as the first system context block; encoded request bodies have an explicit profile bound. Remote endpoints require HTTPS; plaintext is loopback-development-only; credentials/query/fragment URLs, compressed responses, ambient proxies by default, and cross-origin redirects are rejected.
- The OpenAI-compatible mapping supports text/system/developer/tool-result messages, image data references, tools, JSON-schema output, mapped reasoning effort, non-streaming chat responses, streaming text/tool fragments, usage/cached usage, finish reasons, and bounded `org.milkdrift.openai/request` options. The native Anthropic mapping independently handles system blocks, user/assistant/tool-result content, images, tool definitions/calls, Messages API events, usage/finish reasons, required version/auth headers, and bounded `org.milkdrift.anthropic/request` options. Anthropic structured output/developer role/reasoning controls and generic file parts are rejected; explicit continuation and provider-managed sessions are rejected for both until an exact protocol mapping exists.
- Model response, final text, structured output, tool-call data, and bounded provider metadata have separate artifact media contracts and are all committed before output/success reports. A publication failure yields failure, no prompt or response is logged, restricted publication is the production default, and cancellation acknowledgement does not claim provider-side termination.
- `milkdrift-authority` owns canonical `ActorRef`, immutable schema-v1 grant revisions, typed command/control operations, workflow/run/capability/filesystem/network/secret scopes, validity and revocation facts, numeric ceilings, pure deterministic evaluation, schema-v1 decision snapshots and digests, and redacted opaque secret mechanics. `AuthorRef` remains distinct revision provenance.
- External runtime commands present an exact grant revision and revocation generation to an injected evaluator. The unchanged command-v1 bytes are wrapped by authorization-audit schema v1; a decision-bearing command-result schema v2 is committed atomically with accepted or denied results. Exact duplicate command IDs return the original decision/result without reevaluation. Internal system transitions and worker reports use private runtime-owned paths and are rejected by the external command API.
- `milkdrift-control` owns strict schema-v1 control commands and workflow proposals for human, service, process, and model producers. Proposal JSON is byte/depth/item/string bounded, duplicate-key-safe, unknown-field rejecting, canonical, domain-separated digest-bound, and optimistic against exact base revision/digest plus optional live run sequence. It carries closed mutation batches, exact provenance, bounded rationale/risk/assumption lists, evidence and artifact references, application policy, an optional run action, and an untrusted stop claim. Oversized reasoning must remain in an artifact. The model bridge reads structured output only; prose and tool calls are ignored as control intent.
- `ControlService` privately constructs and validates prospective revisions, checks the exact capability/profile/trust/side-effect/budget delta against the caller's ordinary grant, classifies deterministic policy-v1 risk, stores immutable revisions, and uses existing authorized runtime commands for live reconciliation, approval, apply, pause/resume/cancel/retry, signal, create, and start. Low-risk auto-apply is limited to future pure/read-only additions with exact apply authority. Existing/started work, dependencies touching started descendants, terminal changes, side effects, provider/profile/trust expansion, subworkflow/interface changes, cancel/resume/signal, and uncertainty-sensitive work require approval or stronger action authority. Stable derived runtime command and reconciliation identities preserve idempotent replay; stale base/sequence/digest/plan guards fail closed.
- Observer, Advisor, Supervisor, Controller, and Autonomous control presets expand into normal immutable `AuthorityGrant` revisions with the exact caller-supplied run/workflow, capability, budget, validity, and revocation scope. The in-process `milkdrift-workflow-control` capability advertises inspect/propose/pause/resume/apply/retry/signal operations and resolves caller authority through a trusted opaque context reference outside model-owned data. Malformed or adversarial inputs report a normal rejected terminal with no side effect. A bounded controller blueprint builder emits an ordinary acyclic wrapper containing one explicit pinned `Repeat` with hard limits and a human checkpoint.
- Authorization-filtered control read models expose current run lifecycle/revision/digest/usage, node states, latest attempt anchors, exact resolved capability and provider profile snapshots, context-manifest and output/artifact references, side-effect/idempotency facts, terminal failures, late evidence, uncertainty obligations, current reconciliation state, immutable revision lineage, proposal status, and stable-cursor raw event timeline pages. Settled high-frequency detail remains journal history by design.
- `milkdrift-capability-host` owns a bounded live registry and narrow concrete-adapter interface. Registrations are keyed by capability identity plus nonzero descriptor revision; identical duplicates are idempotent, conflicting reuse is rejected, newer revisions become current, and old exact generations remain dispatchable until explicitly drained and reaped. Resolution uses one locked snapshot, requirement matching, configured authority scope, resource budgets, fresh availability, immediate capacity evidence, explicit priority, and stable identity/revision ordering.
- Live host admission has no hidden queue. It acquires an exact-generation permit immediately before adapter entry, tracks the invocation-to-generation owner independently from observation load, routes cancellation exactly, catches adapter panics, releases permits through RAII, distinguishes pre-entry rejection from post-entry uncertainty, closes admission during shutdown, and reports forced-removal owners. Registry queries expose bounded descriptor digests, current/draining state, health/staleness, actual permits, limits, and last failure summaries with authority filtering.
- `SecretResolver` returns non-serializable, non-clone sensitive values with redacted formatting and zero-on-drop storage. Deterministic in-memory test infrastructure remains, and `milkdrift-secret-env` adds the first concrete source: an explicit opaque-reference-to-environment-name map that never enumerates the environment or serializes/retains resolved values.
- `milkdrift-local-process` owns private-invariant process-profile document schema v1. Profiles pin stable profile/capability/descriptor revisions; one namespaced operation; honest side-effect, idempotency, cancellation, restart, and platform facts; one absolute executable; fixed argv templates with explicitly named scalar/path/config/root/invocation/key substitutions; isolated working-directory mode; canonical access roots; selected input paths; cleared/allowlisted environment; secret refs; bounded stdin, stdout, stderr, timeouts, termination deadlines, children observations, input/output counts and bytes, declared regular-file outputs, and bounded namespaced extensions. Profiles contain no shell command and no secret value.
- The local-process adapter validates the exact pinned generation, materializes before resolving only required secrets, canonicalizes executable/workspace roots, starts with `env_clear`, and spawns one `Command` argument vector without a shell. Substitutions cannot add argv entries; missing/unknown inputs, NUL, excessive argv, invalid roots, and non-scalar text substitutions reject before process entry. Secret-bearing profiles cannot stream raw process text; exact secret bytes are redacted from bounded captures before publication.
- `milkdrift-capability-host::materialization` is the narrow host-owned workspace/artifact port. Its production `RuntimeStore` bridge reads exact workspace versions and verified bounded artifact chunks under explicit read authority, creates private temporary workspaces, copies only selected values, and imports only declared regular files or bounded captures through the content-addressed `ArtifactStore`. Relative normal paths, depth/count/byte limits, canonical containment, symlink/hardlink/special-file rejection, stable publication identity, run accounting, restricted sensitivity, invocation producer, exact input causes, and execution provenance are enforced. Incomplete publication streams are aborted; undeclared files remain temporary and are removed with the workspace.
- Process stdout and stderr are drained concurrently through a bounded synchronous channel before wait completion. Capture memory has independent hard bounds; overflow either drains/discards excess or terminates according to the profile. Progress/output/heartbeat counts are validated against the runtime's 1,024-observation bound. Exit code, signal, timeout, output overflow, cancellation, missing output, import failure, and unproven termination map to bounded typed terminal evidence.
- On Unix the child enters a new process group. Graceful/forced signals target the group, the immediate child is reaped, and confirmed cancellation requires observed group disappearance. Surviving descendants after immediate-child success are terminated and reported as a contract failure. Deliberate descendant group/session escape is not prevented and is advertised as unsupported. Non-Unix builds advertise no owned group or terminal group observation; cancellation can remain uncertain rather than claiming descendant cleanup.
- `milkdrift-capability-host::EffectWorkerHost` explicitly owns fixed execution threads, one reserved cancellation/control thread, bounded queues, bounded runtime claim pages, duplicate-cancellation suppression, panic containment, health counters, and drain/cancel/retain shutdown. It stops polling admission before shutdown, never holds the runtime claim gate during external work, and joins all threads on clean shutdown. Forced adapter removal returns exact unresolved invocation owners; retained or lost durable starts remain for runtime recovery.
- Runtime projection folding is exhaustively dispatched into cohesive semantic event-family reducers, while structured runtime coordination delegates repeat, subworkflow, and deterministic reducer mechanics to focused modules. Redb journal/artifact/admin/store responsibilities remain split behind narrow facades; integration and contract tests are grouped by behavior.
- A small inward `milkdrift-contracts` crate owns canonical/duplicate-safe/bounded JSON mechanics and validated-string newtype mechanics used by multiple production domains. Domain crates still own every semantic identity, validation rule, limit, schema version, and error vocabulary.
- Private-invariant, bounded identities and versioned canonical JSON envelopes for capability descriptors and invocation contracts, including one shared bound large enough for every canonical workspace/artifact reference.
- Honest capability feature, cancellation, idempotency, side-effect, admission, locality, trust-zone, usage, and error representations; idempotent writes require an advertised external key scope, and mutable observations remain separate from immutable descriptors.
- Private immutable blueprint revisions with deterministic semantic digests, explicit ancestry, optimistic base checks, and atomic mutation batches.
- Semantic representations and validation for task, conditional branch, fork, join, reducer, explicit repeat, wait, signal, pinned subworkflow, and terminal nodes.
- Typed interfaces, ports, bindings, safe conditions and paths, closed mutations, bounded diagnostics, canonical schema-v1 fixtures, hostile-input tests, property tests, and privacy compile-fail documentation tests.
- A primary CI workflow for formatting, all-feature checks/tests, Clippy, rustdoc, and dependency policy, plus a weekly/manual long-run stress workflow.
- Versioned run commands with actor, idempotency identity, exact aggregate/sequence guard, boundary timestamps, bounded reasons, and durable exact command results.
- Checksummed schema-v1 append-only run events, pure deterministic live-compacting projections, resumable stable-cursor event pages, a bounded projection-snapshot envelope v2 containing runtime projection payload v3, and immutable query/read models. The snapshot wire carries one strict padded standard-Base64 string and checksums decoded raw payload bytes with domain-separated length framing. Hand-reviewed event goldens cover lifecycle/revision control, node output, lease/retry/cancellation/uncertainty, branch/join/repeat, wait/signal/timer, subworkflow, recovery, and reconciliation/remediation families. Full node executions remain live only through dispatch, retry/uncertainty/cancellation, successor, structured-child, import, and reconciliation obligations; closed occurrences collapse to at most one current scope/node terminal summary carrying immutable revision, conservative side-effect, route, and retained output/provenance anchors. Completed branch/join ownership, repeat scopes, and child-workflow links retire after their consumers close. Lifetime events, superseded execution identities, reports, attempts, leases, timers, consumed signals, repeat frontiers, recovery passes, revision pins, and reconciliation plans remain in paged journal history rather than active state; unsupported optional projection snapshots replay from the journal.
- Narrow persistence ports and a production redb adapter coordinating journal append, command and signal idempotency, cumulative history-chain updates, workspace accounting, discovery indexes, and artifact-reference checks in one write transaction. Internal JSON rows use family-bound checksummed schema-v1 envelopes under exact-current document format 6 and physical schema 3. History-chain records v2 may bind a runtime projection-payload commitment to the same accepted journal head; a snapshot is usable only when its payload matches that commitment as well as its covered history digest. Older and future stores are refused; no migration is claimed. Direct reads and bounded resumable scrubs detect malformed, missing, rekeyed, or inconsistent rows without claiming whole-database authenticity or rollback protection. The administrative index scrub preserves integrity-cursor schema v1 and physical phase tags `0..=35` while delegating validation to run, scheduler, workspace, revision, snapshot, and artifact modules.
- Durable run-root, branch, repeat-iteration, and subworkflow workspace scopes with immutable versioned values, sibling isolation, and bounded fail-closed validation of complete parent/root and successor/inheritance/import provenance chains. Paired budget/usage rows retain the sole workspace accounting authority.
- A filesystem content-addressed artifact store with BLAKE3 verification, bounded streaming writes/reads, atomic publication, cross-checked metadata/manifest/digest/ownership/reference rows, default-restricted sensitivity, retention/provenance metadata, and deterministic resumable orphan cleanup. Product-created temp/content paths and delete guards are explicit durable tables updated before filesystem mutation. Publication age comes from an injected boundary clock.
- Deterministic eligibility/condition evaluation, physically bounded distinct-run runnable pages with validated per-run age-first heads, independently rotating bounded maintenance cursors, leases/heartbeats, cancellation intent, conservative retry/uncertainty policy, and graceful admission shutdown. Runtime open performs only schema compatibility checks with admission closed; synchronous startup pages nonterminal runs, validates their authoritative revision/history/workspace and frozen invocation references, performs active lease recovery to a progress-checked fixed point, and admits work only after success. Complete historical verification remains an explicit resumable `StorageAdmin::scan_integrity` operation, with content hashing opt-in; health exposes bounded samples rather than claiming a complete-store proof.
- Structured sequence, branch, fork/join, reducer, repeat, wait/timer/signal, owned subworkflow execution with explicit value import, and terminal behavior through a deterministic capability executor boundary.
- Pure prospective revision reconciliation using stable node/configuration/dependency identities, per-execution structured scopes, persisted classifications/decisions/action facts, and stale-plan guards.
- Focused ADRs for journal/projection ownership, redb/artifact transactions, side-effect truthfulness, prospective reconciliation, shared contract mechanics, immutable proposal revisions, and the shared human/AI control path.

## Limitations

There is no actor authentication/session, peer transport, daemon, wire API, CLI, desktop application, or daemon-owned continuous controller lifecycle. The workflow-control capability is an embeddable in-process adapter; its trusted authority-context resolver and result-artifact publisher are explicit host-supplied ports. Authority grants constrain submitted facts but do not prove actor identity. The control service does not own a separate proposal repository: immutable revisions and live history retain the proposal identity/digest/provenance anchor, while callers preserve the complete proposal as an artifact when required. Context candidate acquisition is expressed as a pure bounded runtime request: the caller pages journal/projection/workspace evidence and supplies exact candidates; there is no separate optimized historical inspector index. The provider adapter currently maps OpenAI chat completions rather than the separate Responses API, has no discovery or pricing calculation, does not map generic file parts or provider-managed sessions, and uses a conservative whole-request cap equal to the smaller request/idle timeout because the blocking HTTP stack exposes no separate per-read timer. Cooperative cancellation closes at the next read/timeout boundary and cannot prove remote termination. Partial streamed fragments are durable observations, but no successful partial-response artifact is claimed after malformed/truncated/uncertain completion.

Local-process profiles provide mediation and ownership, not a sandbox: they do not enforce network isolation, CPU/memory quotas, a maximum child count, or prevention of a malicious Unix descendant creating a new session/process group. Regular-file input/output materialization is implemented; directory artifacts, sparse/special files, writable shared repository mounts, and a complete openat-style directory-handle implementation are not claimed. On non-Unix targets complete process-tree cancellation is not claimed. PID receipts are diagnostics only and are never used to reconnect after restart. Active projection memory is bounded by live semantic state, not universally constant: workflow size, active branches, unresolved/retained effects, output/context/artifact retention, configured workspace limits, and bounded worker ownership remain legitimate growth dimensions. Storage migration and automatic derived-index repair are not implemented; pre-release users must create a new store after incompatible format changes. The synchronous redb adapter still needs a daemon-owned bounded blocking database owner in the daemon slice; `EffectWorkerHost` owns external capability effects, not arbitrary redb calls.
