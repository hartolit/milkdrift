# Status

This document owns current implementation facts and limitations.

## Implemented

- A Rust 1.95.0, edition-2024 workspace with seven safe-Rust packages and a curated lint/dependency policy.
- Runtime projection folding is exhaustively dispatched into cohesive semantic event-family reducers, while structured runtime coordination delegates repeat, subworkflow, and deterministic reducer mechanics to focused modules. Redb journal/artifact/admin/store responsibilities remain split behind narrow facades; integration and contract tests are grouped by behavior.
- A small inward `milkdrift-contracts` crate owns canonical/duplicate-safe/bounded JSON mechanics and validated-string newtype mechanics used by multiple production domains. Domain crates still own every semantic identity, validation rule, limit, schema version, and error vocabulary.
- Private-invariant, bounded identities and versioned canonical JSON envelopes for capability descriptors and invocation contracts, including one shared bound large enough for every canonical workspace/artifact reference.
- Honest capability feature, cancellation, idempotency, side-effect, admission, locality, trust-zone, usage, and error representations; idempotent writes require an advertised external key scope, and mutable observations remain separate from immutable descriptors.
- Private immutable blueprint revisions with deterministic semantic digests, explicit ancestry, optimistic base checks, and atomic mutation batches.
- Semantic representations and validation for task, conditional branch, fork, join, reducer, explicit repeat, wait, signal, pinned subworkflow, and terminal nodes.
- Typed interfaces, ports, bindings, safe conditions and paths, closed mutations, bounded diagnostics, canonical schema-v1 fixtures, hostile-input tests, property tests, and privacy compile-fail documentation tests.
- A primary CI workflow for formatting, all-feature checks/tests, Clippy, rustdoc, and dependency policy, plus a weekly/manual long-run stress workflow.
- Versioned run commands with actor, idempotency identity, exact aggregate/sequence guard, boundary timestamps, bounded reasons, and durable exact command results.
- Checksummed schema-v1 append-only run events, pure deterministic live-compacting projections, resumable stable-cursor event pages, checked bounded projection-snapshot schema v3, and immutable query/read models. Hand-reviewed event goldens cover lifecycle/revision control, node output, lease/retry/cancellation/uncertainty, branch/join/repeat, wait/signal/timer, subworkflow, recovery, and reconciliation/remediation families. Full node executions remain live only through dispatch, retry/uncertainty/cancellation, successor, structured-child, import, and reconciliation obligations; closed occurrences collapse to at most one current scope/node terminal summary carrying immutable revision, conservative side-effect, route, and retained output/provenance anchors. Completed branch/join ownership, repeat scopes, and child-workflow links retire after their consumers close. Lifetime events, superseded execution identities, reports, attempts, leases, timers, consumed signals, repeat frontiers, recovery passes, revision pins, and reconciliation plans remain in paged journal history rather than active state; unsupported optional projection snapshots replay from the journal.
- Narrow persistence ports and a production redb adapter coordinating journal append, command and signal idempotency, cumulative history-chain updates, workspace accounting, discovery indexes, and artifact-reference checks in one write transaction. Internal JSON rows use family-bound checksummed schema-v1 envelopes under exact-current document format 5 and physical schema 3. Older and future stores are refused; no migration is claimed. Direct reads and bounded resumable scrubs detect malformed, missing, rekeyed, or inconsistent rows without claiming whole-database authenticity or rollback protection.
- Durable run-root, branch, repeat-iteration, and subworkflow workspace scopes with immutable versioned values, sibling isolation, and bounded fail-closed validation of complete parent/root and successor/inheritance/import provenance chains. Paired budget/usage rows retain the sole workspace accounting authority.
- A filesystem content-addressed artifact store with BLAKE3 verification, bounded streaming writes/reads, atomic publication, cross-checked metadata/manifest/digest/ownership/reference rows, default-restricted sensitivity, retention/provenance metadata, and deterministic resumable orphan cleanup. Product-created temp/content paths and delete guards are explicit durable tables updated before filesystem mutation. Publication age comes from an injected boundary clock.
- Deterministic eligibility/condition evaluation, physically bounded distinct-run runnable pages with validated per-run age-first heads, independently rotating bounded maintenance cursors, leases/heartbeats, cancellation intent, conservative retry/uncertainty policy, and graceful admission shutdown. Runtime open performs only schema compatibility checks with admission closed; synchronous startup pages nonterminal runs, validates their authoritative revision/history/workspace and frozen invocation references, performs active lease recovery to a progress-checked fixed point, and admits work only after success. Complete historical verification remains an explicit resumable `StorageAdmin::scan_integrity` operation, with content hashing opt-in; health exposes bounded samples rather than claiming a complete-store proof.
- Structured sequence, branch, fork/join, reducer, repeat, wait/timer/signal, owned subworkflow execution with explicit value import, and terminal behavior through a deterministic capability executor boundary.
- Pure prospective revision reconciliation using stable node/configuration/dependency identities, per-execution structured scopes, persisted classifications/decisions/action facts, and stale-plan guards.
- Focused ADRs for journal/projection ownership, redb/artifact transactions, side-effect truthfulness, prospective reconciliation, and shared contract mechanics.

## Limitations

There is no live capability registry, provider/process/model adapter, causal context builder, secret store, authority-policy engine, peer transport, daemon, wire API, CLI, or desktop application. The included executor is deterministic test infrastructure, not a production provider. Active projection memory is bounded by live semantic state, not universally constant: workflow size, active branches, unresolved/retained effects, output/context/artifact retention, configured workspace limits, and bounded worker-ownership evidence remain legitimate growth dimensions. Historical attempt/progress/recovery/reconciliation detail is available as internal durable journal event pages; no separately versioned, authorization-aware external historical read-model API exists yet, and the event storage schema is not that future API. Projection compaction does not delete run events, artifact content/metadata, workspace output records, or exact journal provenance: stable summaries and references remain available for a future Iced timeline/inspector and causal-context builder to resolve through the journal. Workspace/artifact limits are enforced locally; provider cost/resource observations remain evidence and require Pass 3 policy integration for broader spend/resource authority. Storage migration and automatic derived-index repair are not implemented; pre-release users must create a new store after incompatible format changes. Optional projection snapshot v1 and v2 payloads are deliberately discarded and replayed, not migrated. Arbitrary files injected outside the current artifact publication protocol are outside cleanup ownership. The synchronous redb adapter must be placed behind a bounded blocking owner when a future async daemon hosts it.
