# Status

This document owns current implementation facts and limitations.

## Implemented

- A Rust 1.95.0, edition-2024 workspace with twenty-one safe-Rust packages and a curated lint/dependency policy.
- Prompt-sequence schema 1 accepts bounded duplicate-safe JSON or a Markdown header plus exact per-stage prompt sections. It names only preconfigured capability/profile requirements and an opaque repository workspace policy, compiles to ordinary task/branch/signal-wait/terminal nodes, assigns fresh causal context to coding/review stages, and records import/repository/prompt digests and stage mappings in immutable revision metadata. Verification success is an explicit artifact-presence fact; failure prevents later stages and routes to review plus the shared durable approval wait. Bounded remediation builds a normal digest- and sequence-guarded prospective proposal that inserts fresh remediation, re-verification, re-review, and renewed approval without rewriting completed occurrences or changing the frozen run grant.
- The daemon and thin CLI expose prompt-sequence validate/import/show/status/stage/remediate operations through the existing authorized command/read plane. Historical timeline entries lead to exact attempt inspection after frontier compaction, including frozen capability/process provenance and separately authorized causal-context detail. A real daemon/redb/local-process integration proof uses a persistent temporary repository, fresh byte-pinned process invocations, a weak verifier, independent review, proposal approval/apply, three restart boundaries, explicit signal/resume, and asserts no duplicate attempts.
- `milkdrift-daemon` is the authoritative local host. One dedicated thread owns synchronous redb, artifact, runtime, control, and adapter lifecycle access behind a bounded `sync_channel`; Axum reactor tasks receive overload instead of blocking or growing an unbounded queue. Focused internal owners cover command application and receipts, revision lineage, runs/attempts/timelines, layouts, proposals, artifacts, and capability registration/read models. One injected `GrantSetEvaluator` authorizes every externally initiated command and information-bearing local query before its owner runs. The daemon recovers runtime admission closed, validates application state, registers and health-checks configured adapters, recovers peer work, starts fixed bounded effect workers, resumes runtime admission, and only then becomes ready. A configured maintenance notification interval drives scheduler/effect progress without a busy loop.
- Daemon configuration schema 3 covers a loopback bind, owned data root, file/environment secret references, credential-to-actor/grant bindings, explicit workflow/run/capability/filesystem/network/secret/artifact/layout/peer/daemon/workspace scopes and numeric ceilings, fixed scheduler/effect/request bounds, process/model profile sources, explicit peer relationships, application-receipt/audit retention, and drain/cancel/retain shutdown policy. The retained `command_ledger_bound` configuration spelling now limits non-evicting external application receipts and independently bounded audit records; exhausting receipt capacity rejects new command identities rather than discarding idempotency truth. Wildcard, unknown-side-effect, omitted-operation, infinite-validity, or unbounded grants require the visually explicit `dangerous_allow_broad_authority` acknowledgement; empty protected scopes deny access and safe configurations fail closed. Older schemas are rejected rather than silently widened. Validation and path normalization happen before storage opens. Non-loopback plaintext, missing credentials, permissive file permissions, unknown fields, invalid versions, and invalid bounds fail closed. Redacted effective configuration never includes resolved values.
- Local HTTP authentication is mandatory. Credential references are reread on use for rotation, file credentials require private permissions on Unix, digest comparison is constant-time, and actor/grant/revocation facts come only from server configuration. An `ActorSession` contains the actor, exact expanded immutable grant revision, and a redacted credential-derived cursor key; it contains no executable preset state. Authentication never implies access. CORS is disabled and Authorization, environment, prompts, outputs, artifacts, and resolved secrets are excluded from public diagnostics and default tracing.
- `milkdrift-control-protocol` is a pure protocol-1.0 package with duplicate-safe bounded JSON, explicit negotiation, stable error/result envelopes, actor-free idempotent command requests, authenticated cursor schema 2 bound to actor/exact-grant/decision/resource-filter plus credential-derived MAC, immutable revision/diff models, compact run/node/attempt/proposal models, projected timeline categories, capability/authority/artifact/health reads, and external SSE observations. Internal events, redb keys, snapshots, provider objects, process handles, and framework types are not wire contracts.
- Layout document schema 1 stores only exact workflow/revision association, bounded node presentation, groups/annotations, viewport, authenticated author, generation, and an independent digest. Each layout is persisted as an independent checked redb application record outside immutable semantic revisions with optimistic generation checks; changing it cannot change semantic revision identity.
- The control API exposes authority-checked version negotiation, coarse readiness, detailed health, one idempotent command endpoint, bounded revisions/diffs, runs/nodes/attempts/timelines, proposal status, capabilities/providers, filtered peers, current authority, artifact metadata/ranges, layouts, run SSE, capability SSE, and daemon-health SSE. Every route is declared through a typed operation/resource registration macro enforced by a guard test. Owner dispatch resolves workflow/resource facts before evaluation, filters collections before projection, and returns stable bounded authorization reason/digest detail. External application receipts bind actor, command schema/digest, exact grant identity/revision/digest, accepted or intentionally durable rejected result bytes, effect reference, and timestamps. Exact replay returns the stored result; conflicting reuse fails. Proposal discovery uses its own durable validated projection rather than scanning receipts.
- Page and SSE continuations fail closed across actors, credentials, grant replacement, and resource/filter changes. Open local streams reauthenticate and reevaluate every bounded polling cycle; peer observation streams do the same and report authorization termination separately from transport failure. Capability feed retention is partitioned by authority-scope digest, so hidden generations do not affect visible counts, ordering, snapshots, or cursors.
- `milkdrift-control-client` owns the complete HTTP mapping, negotiation, redacted bearer handling, typed page/query/command methods, bounded safe-query retry classification, explicit artifact ranges, and resumable SSE parsing. Mutating calls are never implicitly retried. `milkdrift-cli` is a storage-free thin client covering daemon, blueprint, run, node, attempt, proposal, capability, peer, artifact, and layout operations with human output, stable JSON schema 1, confirmations, explicit download destinations, reconnect status, and stable exit categories.
- `milkdrift-peer-protocol` is a transport-neutral protocol-1.0 package with duplicate-safe bounded envelopes, explicit version negotiation, authenticated session cross-checks, expiring digest-bound catalog snapshots, exact invocation/delegation/acceptance contracts, monotonic resumable observation pages, separate cancellation acknowledgements, and metadata-first bounded artifact transfer. It has no Tokio, Axum, Reqwest, redb, provider, process, or UI dependency.
- `milkdrift-peer-http` provides the distinct `/peer/v1` realm, Rustls HTTPS client, explicit loopback-development exception, request-time rotating bearer authentication mapped to configured `PeerId`, default-deny relationship authority, capability/operation filters, request-rate/concurrency/duration/cost/observation/artifact quotas, graceful drain/revocation, and bounded redacted HTTP behavior. Relationship action/filter configuration expands once into ordinary immutable grants; the same evaluator covers handshake, catalog/provider/health, invocation, execution reads/streams, cancellation, and artifact transfer. Accepted peer invocations persist the exact allowing authority decision. Operator URLs are fixed configuration and redirects are disabled.
- Serving peers derive scoped catalogs from live capability-host generations. Consuming peers verify catalog digest/expiry and register collision-resistant ordinary remote adapters with exact typed peer/catalog/capability provenance, `Locality::Peer`, and configured trust zones. Replacement, disconnect, drain, revocation, and expiry stop new resolution without making catalogs durable workflow truth; the runtime still records one exact ordinary resolved snapshot.
- Remote direct-adapter execution uses transactional redb primary/request/dispatch/claim/terminal/accounting indexes. Acceptance atomically checks exact replay, relationship/catalog generations, authority and per-peer/global/queue/retention capacity. Fixed daemon-owned workers claim the durable queue; claim and adapter entry are distinct CAS boundaries, partial spawn is joined, panic/restart requeues only pre-entry work, and entered work without terminal evidence becomes uncertainty. Observations are separate checksummed append-only rows with bounded cursor pages. Cancellation request/acknowledgement/terminal evidence and disconnect remain separate facts, late terminal evidence is idempotent, and explicit archival preserves idempotency/provenance/security facts.
- Peer requests carry exact originating run/revision/node/execution/attempt coordinates into the serving adapter context. Reconnect after a drained cached catalog creates a fresh local registration generation. Inbound process/model host-resource access remains default deny and requires explicit relationship filesystem/network/secret scopes in addition to capability/operation/side-effect authority.
- Peer artifact upload/download is an adapter over the ordinary core artifact publication and authorized range-read ports. Incomplete content uses resumable core temp inventory, is invisible until exact digest/size verification, and retains sensitivity, retention, remote producer, and origin peer/execution provenance. Ordinary content-addressed deduplication and core orphan/retention policy apply; there is no peer filesystem artifact repository.
- Peer artifact staging exchanges exact digest/size/media type and authority metadata before raw bytes, uses sequential chunks or bounded ranges, resumes owned temporary uploads, verifies content before digest-derived atomic publication, and deduplicates only verified published content. Aborts and mismatches hide/remove incomplete content; secret/config media types, arbitrary paths, and over-quota transfers are rejected.
- Blueprint task configuration schema v2 owns an immutable context policy with direct-input, graph-depth, exact-node/execution, selected-workspace/explicit-evidence, semantic-role, category, artifact-metadata, ordering/truncation, fresh/continuation, fail-closed, and discovery/item/artifact/byte/per-item/event/manifest/provider-unit bounds. Task output semantic roles are declared by the immutable task definition rather than guessed from filenames or prose. Custom readers validate hostile selector and budget shapes. Blueprint revision and mutation readers deliberately refuse v1 because inventing a policy would change semantic identity; canonical v2 fixtures preserve the established digest when new optional fields are absent.
- `milkdrift-model` owns provider-neutral schema-v1 model-task/model-response envelopes and the schema-v2 context-manifest body. A manifest binds exact run/revision/node/execution/attempt and policy facts; semantic tags; source content digest, revision, execution, scope, sequence, and occurrence; producer actor/capability/descriptor/provider/peer/invocation; ordered causal evidence; selected sizes and sensitivity/authority; stable reasons/omissions; totals/budget; and a verified domain-separated digest. V1 manifest bodies are deliberately refused because they cannot prove materialized content or exact producer provenance.
- `milkdrift-runtime::context::source` is the single production candidate-source boundary over the frozen journal head, historical revision graph, workspace, artifact metadata, scopes, and initiating execution-authority basis. It discovers direct inputs, bounded ancestors, exact nodes/executions, tagged outputs, failures/cancellations/uncertainty/decisions, joins/imported subworkflow results, selected workspace values, artifacts, and explicit event/node/artifact evidence as metadata first. Historical executions keep their governing revision, joined failures may cross the explicit join boundary, successful sibling output remains isolated, and branch/authority omissions are redacted. The pure selector applies stable causal ordering and every configured bound before selected-content reads. Required denied, missing/corrupt, unsupported, or over-budget evidence fails before dispatch.
- Invocation-request schema v2 has one explicit typed context-manifest artifact reference plus only the selected non-direct evidence as reserved exact inputs. The runtime commits and journal-publishes the restricted canonical manifest artifact before `NodeScheduled`, then materializes only those selected values/artifacts through authorized host ports and verifies digest, size, media type, and attempt. Retry attempts rebind the prior frozen selection without rescanning newer history. The context-free v1 invocation compatibility path remains unambiguous. Local-process profiles can explicitly materialize `milkdrift.context_manifest` and selected reserved inputs through existing input-file rules; no implicit context file exists.
- `milkdrift-model-provider` implements a live `model.generate` adapter with non-secret endpoint-profile schema v1, explicit profile revision/model alias/protocol/auth refs/limits/redirect/TLS/proxy/host/trust/features/options, bounded reqwest/rustls transport, strict SSE parsing, feature negotiation before entry, scoped secret resolution, cooperative cancellation, and committed output artifacts. A Fresh request verifies the exact manifest against its attempt, sends the canonical manifest as the first system context block, and maps only manifest-selected text/JSON and supported images as explicitly delimited untrusted evidence. Digest/size/media mismatches, extra reserved context, and unsupported generic binary evidence reject before HTTP. Encoded request bodies retain an explicit profile bound. Remote endpoints require HTTPS; plaintext is loopback-development-only; credentials/query/fragment URLs, compressed responses, ambient proxies by default, and cross-origin redirects are rejected.
- The OpenAI-compatible mapping supports text/system/developer/tool-result messages, image data references, tools, JSON-schema output, mapped reasoning effort, non-streaming chat responses, streaming text/tool fragments, usage/cached usage, finish reasons, and bounded `org.milkdrift.openai/request` options. The native Anthropic mapping independently handles system blocks, user/assistant/tool-result content, images, tool definitions/calls, Messages API events, usage/finish reasons, required version/auth headers, and bounded `org.milkdrift.anthropic/request` options. Anthropic structured output/developer role/reasoning controls and generic file parts are rejected; explicit continuation and provider-managed sessions are rejected for both until an exact protocol mapping exists.
- Model response, final text, structured output, tool-call data, and bounded provider metadata have separate artifact media contracts and are all committed before output/success reports. A publication failure yields failure, no prompt or response is logged, restricted publication is the production default, and cancellation acknowledgement does not claim provider-side termination.
- `milkdrift-authority` owns canonical `ActorRef`, `PeerId`, immutable schema-v2 grant revisions and digests, typed command/query/control/capability/artifact/layout/peer/daemon operations, workflow/run/capability/filesystem/network/secret/artifact/layout/peer/daemon/workspace scopes, locality/peer/trust-zone/execution-trust envelopes, validity and revocation facts, cost/duration/invocation/artifact/unit/concurrency ceilings, pure deterministic evaluation, schema-v1 decision snapshots and digests, immutable execution-authority bases, adapter execution requirements, and redacted opaque secret mechanics. `AuthorRef` remains distinct revision provenance.
- External runtime commands present an exact grant revision, digest, and revocation generation to an injected evaluator. The unchanged command-v1 bytes are wrapped by authorization-audit schema v1; a decision-bearing command-result schema v2 is committed atomically with accepted or denied results. Exact duplicate command IDs return the original decision/result without reevaluation. Starting a run commits its immutable actor/grant/policy/workflow/run/revision/decision basis before `RunStarted`; structured child runs inherit it. Internal system transitions and worker reports use private runtime-owned paths and are rejected by the external command API.
- Start and revision-adoption planning recursively validate reachable task, reducer, repeat, and subworkflow capability envelopes against the frozen run basis without depending on live availability. An out-of-envelope requirement is a typed durable command denial, so draft creation or proposal storage cannot grant execution authority. An AI controller follows the same path and cannot enlarge its own grant.
- `milkdrift-control` owns strict schema-v1 control commands and workflow proposals for human, service, process, and model producers. Proposal JSON is byte/depth/item/string bounded, duplicate-key-safe, unknown-field rejecting, canonical, domain-separated digest-bound, and optimistic against exact base revision/digest plus optional live run sequence. It carries closed mutation batches, exact provenance, bounded rationale/risk/assumption lists, evidence and artifact references, application policy, an optional run action, and an untrusted stop claim. Oversized reasoning must remain in an artifact. The model bridge reads structured output only; prose and tool calls are ignored as control intent.
- `ControlService` privately constructs and validates prospective revisions, checks the exact capability/profile/trust/side-effect/budget delta against the caller's ordinary grant, classifies deterministic policy-v1 risk, stores immutable revisions, and uses existing authorized runtime commands for live reconciliation, approval, apply, pause/resume/cancel/retry, signal, create, and start. Existing/started work, dependencies touching started descendants, terminal changes, side effects, provider/profile/trust expansion, subworkflow/interface changes, cancel/resume/signal, and uncertainty-sensitive work require approval or stronger action authority. Stable derived runtime command and reconciliation identities preserve idempotent replay; stale base/sequence/digest/plan guards fail closed.

No `may_*` or preset boolean decides executable permission. The in-process `milkdrift-workflow-control` capability advertises inspect/propose/pause/resume/apply/retry/signal operations and resolves caller authority through a trusted opaque context reference outside model-owned data. Malformed or adversarial inputs report a normal rejected terminal with no side effect. A bounded controller blueprint builder emits an ordinary acyclic wrapper containing one explicit pinned `Repeat` with hard limits and a human checkpoint.
- Authorization-filtered control read models expose current run lifecycle/revision/digest/usage, node states, exact current or historical attempt anchors, resolved capability/descriptor/provider/peer linkage, frozen capability snapshot/trust/implementation provenance, context-manifest and output/artifact references, side-effect/idempotency facts, terminal failures, late evidence, uncertainty obligations, current reconciliation state, immutable revision lineage, proposal status, and authenticated-cursor raw event timeline pages. - `milkdrift-capability-host` owns a bounded live registry and narrow concrete-adapter interface. Registrations are keyed by capability identity plus nonzero descriptor revision; identical duplicates are idempotent, conflicting reuse is rejected, newer revisions become current, and old exact generations remain dispatchable until explicitly drained and reaped. Resolution uses one locked snapshot and canonical authority evaluation of every exact descriptor candidate before fresh availability or capacity evidence, followed by explicit priority and stable identity/revision ordering. Placement filters distinguish local and typed peer identities; an unavailable allowed generation never causes fallback to a disallowed locality or peer.
- Live host admission has no hidden queue. The runtime durably records the authorized resolution before lease dispatch, reevaluates the exact stored generation at claim, and reevaluates again immediately before adapter code. Process, model, workflow-control, and peer adapters declare their filesystem/network/secret/budget requirements through the same host contract and receive the frozen basis plus resolution/final-entry decisions in their execution context. Typed revocation or narrowing denial releases the lease and never calls adapter code. Once adapter entry occurred, later revocation cannot invent a different terminal outcome. Exact-generation permit ownership, cancellation routing, panic containment, drain/reap behavior, and bounded registry queries remain unchanged.

Profiles bind equal nonzero profile/descriptor revisions; `TrustedHostProcess`; one namespaced operation; operator-declared BLAKE3 executable digest and size plus optional package/deployment and documentation references; honest side-effect, idempotency, cancellation, restart, and platform facts; one absolute executable; fixed argv templates with explicitly named scalar/path/config/root/invocation/key substitutions; isolated working-directory mode; canonical access roots; selected input paths; cleared/allowlisted environment; secret refs; bounded stdin, stdout, stderr, timeouts, termination deadlines, children observations, input/output counts and bytes, declared regular-file outputs, and bounded namespaced extensions. Profiles contain no shell command and no secret value. Path-only schema v1 and unsupported future versions are explicitly refused.
- Registration resolves the executable under an execute root, streams at most 1 GiB through bounded BLAKE3 hashing, verifies exact bytes/size, regular-file/executable facts and stable open-file/path observations, and only then constructs the immutable descriptor. Its namespaced provenance freezes safe configured/canonical path digests, implementation/content/size/package/platform evidence, full profile digest, execution-policy digest, trust class, and process-ownership facts. Health revalidates that identity and makes a mismatched generation sticky-unavailable; restoration does not revive it. The adapter rehashes and revalidates again immediately before spawn, rejects before child entry on mismatch, records the exact verified identity in bounded progress after successful entry, and requires explicit registration of a new revision for changed tooling.
- The local-process adapter materializes before resolving only required secrets, canonicalizes executable/workspace roots, starts with `env_clear`, and spawns one `Command` argument vector without a shell. Substitutions cannot add argv entries; missing/unknown inputs, NUL, excessive argv, invalid roots, non-scalar text substitutions, and exact sandbox requirements reject before process entry. Secret-bearing profiles cannot stream raw process text; exact secret bytes are redacted from bounded captures before publication. Private `identity`, `prepare`, `spawn`, `streams`, `monitor`, `outputs`, `reporting`, and `platform` modules own the former concentrated process responsibilities.
- `milkdrift-capability-host::materialization` is the narrow host-owned workspace/artifact port. Relative normal paths, depth/count/byte limits, canonical containment, symlink/hardlink/special-file rejection, stable publication identity, run accounting, restricted sensitivity, invocation producer, exact input causes, and execution provenance are enforced. Incomplete publication streams are aborted; undeclared files remain temporary and are removed with the workspace.
- Process stdout and stderr are drained concurrently through a bounded synchronous channel before wait completion. Capture memory has independent hard bounds; overflow either drains/discards excess or terminates according to the profile. Progress/output/heartbeat counts are validated against the runtime's 1,024-observation bound. Exit code, signal, timeout, output overflow, cancellation, missing output, import failure, and unproven termination map to bounded typed terminal evidence.
- On Unix the child enters a new process group. Graceful/forced signals target the group, the immediate child is reaped, and confirmed cancellation requires observed group disappearance. Surviving descendants after immediate-child success are terminated and reported as a contract failure. Deliberate descendant group/session escape is not prevented and is advertised as unsupported. Non-Unix builds advertise no owned group or terminal group observation; cancellation can remain uncertain rather than claiming descendant cleanup.

## Limitations

Peer support has no discovery, NAT traversal, VPN/overlay routing, hosted coordinator, automatic certificate authority, mutual-TLS identity mapper, shared database/workflow truth, distributed consensus, model synchronization, tensor transfer, browser client, or Iced desktop application. The daemon continues to bind its own listener only on loopback; public/LAN deployment requires operator-managed HTTPS reverse proxy or private connectivity. Bearer authentication is implemented, while mTLS termination is external. Catalog connection/reload is explicit rather than a continuously reconnecting discovery loop. Peer artifacts use ordinary core publication/read authority, but automatic transfer of every runtime artifact reference is not claimed. File-backed credential values rotate at request time; relationship identity, allowlist, resource scope, quota, and durable revocation-generation configuration changes require restart. Production internet hardening beyond the documented Rustls client, fixed endpoints, bounds, rate/concurrency controls, and loopback two-daemon tests is not claimed.

The daemon has no dynamic adapter/profile/grant reload lifecycle beyond explicit peer catalog reload; local grant narrowing/revocation currently takes effect by validated restart plus credential/revocation changes. There is no public local artifact upload/publication API, global event firehose, public configuration/audit/shutdown route despite their reserved authority vocabulary, generalized plugin framework, optimized lifetime historical-attempt index, context search service, or daemon-owned continuous controller lifecycle. Historical attempt inspection pages the journal and therefore trades bounded memory for scan time. Prompt-sequence schema 1 supports verification-artifact checkpoints only; an explicit checkpoint capability and automatic two-daemon dogfood profile are future additions. Its stage/sequence budgets are requested declarative ceilings composed with enforced run-grant, runtime, adapter, workspace, artifact, and proposal bounds rather than a second accounting engine. Proposal list discovery pages a first-class durable projection while exact proposal truth is still queried through `milkdrift-control`; complete proposals remain immutable documents/artifacts rather than a new mutable repository. The provider adapter currently maps OpenAI chat completions rather than the separate Responses API, has no discovery, tokenizer, or pricing calculation, does not map generic file parts or provider-managed sessions, and therefore enforces provider-unit estimates only when supplied and does not invent context-cost estimates. It uses a conservative whole-request cap equal to the smaller request/idle timeout because the blocking HTTP stack exposes no separate per-read timer. Cooperative cancellation closes at the next read/timeout boundary and cannot prove remote termination. Partial streamed fragments are durable observations, but no successful partial-response artifact is claimed after malformed/truncated/uncertain completion.

Local-process profiles provide mediation and ownership, not a sandbox: `TrustedHostProcess` code runs with daemon-account host privileges. The adapter does not enforce network isolation, CPU/memory quotas, a maximum child count, or prevention of a malicious Unix descendant creating a new session/process group. Portable safe Rust also cannot guarantee atomic execution of the already-hashed handle on every target; the open-file/path consistency checks and final streaming revalidation minimize but do not eliminate the replacement race before OS entry. Regular-file input/output materialization is implemented; directory artifacts, sparse/special files, writable shared repository mounts, and a complete openat-style directory-handle implementation are not claimed. On non-Unix targets complete process-tree cancellation is not claimed. PID receipts are diagnostics only and are never used to reconnect after restart. Active projection memory is bounded by live semantic state, not universally constant: workflow size, active branches, unresolved/retained effects, output/context/artifact retention, configured workspace limits, and bounded worker ownership remain legitimate growth dimensions. Storage migration is not implemented; pre-release users must create a new store after incompatible format changes. Proposal-index rebuilding is explicit rather than automatic. Legacy `control-state-v1.json` is refused at daemon startup so obsolete sidecar idempotency truth is never silently ignored or mixed with redb authority.
