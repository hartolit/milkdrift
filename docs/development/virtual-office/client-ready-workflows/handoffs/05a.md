## Policy choices and limits

Root Cargo lint tables own the required compiler and individual Clippy rules; root `clippy.toml`
owns typed API restrictions. Existing unsafe/must-use/panic/debug policy is preserved. New rules
cover lint/configuration integrity, visibility, ignored outcomes/destructors, conversions, indexing,
public error/panic documentation, stdout/exit ownership and selected copy/allocation/API decay.
`needless_collect` is explicitly enabled: it is allow-by-default on this pinned Clippy, despite the
checklist's description of existing normal coverage. There is no blanket pedantic/nursery/restriction gate.

Arithmetic is required in contracts, workspace budgets, persistence accounts, redb and serving
artifacts, and runtime projection. Closed-state wildcard checking applies in authority evaluation,
managed resources and runtime projection. Indexed access is required workspace-wide; 05b must
inspect exact-size or validated access rather than replace it with panics or blanket exemptions.
Typed probes prove std/Tokio unbounded-channel restrictions and Box/Vec leak restrictions through
aliases. Clippy did not detect the tested builtin `include!` through `disallowed_macros`; that
ineffective configuration was removed. Source checks reject direct and canonically imported/renamed
source inclusion; they do not claim arbitrary macro expansion or name resolution.

A bounded pedantic/nursery survey took 33.59 seconds. These candidates remain review findings:
`needless_pass_by_value`, `trivially_copy_pass_by_ref`, `unnecessary_wraps`, `large_stack_arrays`,
`large_futures`, `large_types_passed_by_value`, `struct_excessive_bools`, `fn_params_excessive_bools`
and `significant_drop_tightening`. Concrete reasons: process pipe ownership survives apparently
unused parameters; local-secret's Unix infallible conversion shares a fallible non-Unix interface;
process observation booleans represent independent stream/termination facts; identity hashing uses
a fixed streaming buffer; identity revalidation retains a lock around sticky failure state.
No measurement justified global future boxing or lower size thresholds. Style/constant-function
suggestions and `redundant_pub_crate` were not made hard gates; existing size/cohesion review and
public boundary checks own those concerns.

`allow_attributes` is not global: a narrow reasoned allow can be correct for target-dependent
diagnostics; stable expectations must remain fulfilled. Existing reasonless suppressions are
required failures, not grandfathered exceptions. `unused_crate_dependencies` is unsuitable for
the evidence package's multiple binaries; machete and dependency graphs remain required.
`explicit_outlives_requirements` already belongs to the inherited idiom group. Qualification style
remains review work, and stable builds cannot use the unstable `must_not_suspend` attribute.
No custom await-invalid type was added: the managed `TransitionGuard` elects a driver without
retaining a mutex, and lifetime/capacity protection may intentionally span suspension. Process/task
completion, ambient-state ownership, lock ordering and filesystem races still need mechanism review
and behavioral evidence; typed restrictions cannot prove them. No changed concurrency mechanism
justified Loom, Miri or a sanitizer run here.
