## Usable operation and ownership

The [operator recipe](../../../../../examples/operator/README.md#author-a-model-workflow) gives
tested commands for `workflow new`, `models`, `input`, `add`, `connect`, `output`, `inspect`, `save`
and `open`. `prompt`, `model`, `disconnect`, `move`, `remove` and `rename` edit the same draft.
Prompts accept a UTF-8 file or `-`. Release-notes and meeting-summary workflows coexist.

`Command::AuthorBlueprint` accepts a workflow/base/mutations draft, optional `BlueprintEdit`, and
`save`. `ConstructBlueprint` accepts an explicit complete mutation batch for richer definitions.
The daemon's private `host/commands/authoring` owner uses existing blueprint, model and acceptance
constructors. Clients retain returned mutations and identities. No draft database, new workflow
language, executor, or CLI-owned construction rule was added. Offline `blueprint create`/`govern`
remain for the separately maintained governed-method bootstrap before daemon configuration.

Saving an unchanged draft returns the same revision; changed saves produce an immutable child.
The command revision guard must equal the draft's exact base. File locks, unchanged-byte checks,
optional `--expected-edit`, create-new destinations and atomic replacement protect local edits.
Separate draft files may deliberately branch from an old immutable base. Unsupported rich
definitions refuse editing before a draft/revision write. File tests establish interruption before
promotion and normal cleanup, not filesystem power-loss durability or forced-kill temp cleanup.

The [ADR](../../../../decisions/0044-public-workflow-authoring.md) owns compatibility and design.
Only control protocol moves to 2.12; draft files use schema 1. Blueprint/model/storage versions stay
unchanged. Protocol default/all-feature API inventories are identical under `target/public-api/`.
New external types have CLI/daemon consumers; graph generation and catalogue adaptation stay private.
