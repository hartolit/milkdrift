## Changes and removals

- `ea8e21a` moves `invocation prepare` construction to the existing capability-host serving owner.
  `POST /v1/invocations/prepare`, `DirectInvocationDraft` and `ControlClient::prepare_invocation`
  expose explicit choices and return the exact current request. The CLI's descriptor/catalog
  selection, provider derivation, wall-clock deadline, idempotency rule and direct-input policy
  checks were removed. Current serving authority and input validation are reused, and the
  authenticated basis has one private constructor shared with submission. Preparation accepts
  no work; the existing direct/published submission and replay owners are unchanged.
- `f17b50d` removes repeated range-position/body-length checks from CLI downloads. The shared
  client owns HTTP range validity and rejects empty nonfinal invocation chunks for every caller.
  The file owner still checks immutable metadata across chunks and the complete size/digest
  before publishing a create-new file. A regression distinguishes stalled chunks from valid
  empty completed artifacts.
- `06ce38b` adds `independent_client::` under daemon `control_plane`. It launches the actual daemon,
  authors/saves from JSON, uploads a brief, starts, downloads the declared accepted output, restarts
  and replays the retained request, refuses changed bytes and copies an independent definition.
  The external fixture stays at two calls. It discards the initial reply to exercise recovery;
  the existing `inputs_cli::` cases separately exercise actual transport loss. Shared binary
  process ownership moved out of the CLI test module into `binary.rs` without duplicate launchers.

Control protocol is now 2.16; clients and daemon upgrade together. Peer transport and durable
invocation/blueprint/journal/receipt formats are unchanged. See
[ADR 0048](../../../../decisions/0048-serving-owned-client-preparation.md).
The public surface adds only the draft contract and its two concrete owner/transport methods.
Default/all-feature inventories are under `target/public-api/milkdrift-*.05.*.txt`; client and peer
protocol pairs match, and host-only test-support exports remain gated. Control-protocol and daemon
exports remain unchanged. No dependencies, stores, schedulers or frontend code were added.

The trace through authoring, starts/recovery, results/repair, copy/publication and learning found
their product decisions in the existing daemon/domain owners. CLI draft files, prompt/file reads,
form choices, overall observation deadlines and create-new downloads remain client concerns.
Offline governed bootstrap and process-sequence compilation retain their distinct existing purpose;
they are not required by the ordinary model-workflow client tested here.
