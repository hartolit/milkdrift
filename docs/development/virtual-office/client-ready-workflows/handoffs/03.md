## Supported operator route

Use `milkdrift run result RUN --details` and `milkdrift run result RUN --field notes --output NEW_FILE`.
The [recovery guide](../../../../guides/headless-dogfood.md#repair-a-held-model-result) owns the full
pause, prepare, submit, inspect, approve, apply, signal and resume recipe. The
[operator example](../../../../../examples/operator/README.md#author-a-model-workflow) connects it
to the release-notes workflow.

`proposal repair RUN review --proposal ID --new-step repair --model CAPABILITY --prompt FILE
--maximum-output-units 512 --file NEW_PROPOSAL_FILE` prepares an ordinary proposal at the **final
model step's rejected-completeness review hold**, with the run paused and its exact revision and
sequence. Preparation does not alter the run. Submission, approval and application retain the
existing control authority, risk, agreement and reconciliation checks. The selected failed
response and original run-input bindings feed new work; a fresh completeness check gates its
result. The original failed check and completed history remain unchanged.

The convenience refuses richer definitions and cannot recursively repair the resulting graph.
Signalling the unchanged hold first reaches its failure terminal. Ended runs cannot resume;
authorized result views offer a new start linked by `recovery_observation=OLD_RUN`, with new
identities and explicitly supplied inputs. This does not transfer private history.
