## Operation and owners

The [operator recipe](../../../../../examples/operator/README.md#author-a-model-workflow) supplies
the Harbor Host and Lantern Rally briefs to one saved release-notes revision. Start with
`run start RUN WORKFLOW REVISION --input brief=FILE --request-file NEW_FILE`. Repeated `--input`
accepts bounded UTF-8 files or one stdin source. Already uploaded artifacts use `--inputs FILE`
with a JSON array of `RunInput` name/artifact identities. Ordinary fields require
`milkdrift.artifact-reference` v1; published choices/artifacts retain their separate contract.

The daemon resolves artifact metadata and content under the caller's authority, checks bytes,
digest and budgets, then creates initial workspace values. Runtime admission still owns declared
and required names, initial references and committed-artifact accounting for ordinary and published
runs. No runtime input database, new execution primitive or publication permission was added.

`ControlClient::prepare_run` records the authenticated host, actor and exact grant with the full
start envelope. The CLI persists a bounded schema-1 record before submission. It contains identities,
guards, reason and evidence, without credentials, source paths or source bytes. Files are explicit
create-new destinations with atomic promotion; Unix uses mode 0600 and rejects exposed or linked
records. Keep a record while recovery is needed and remove it deliberately afterward; no automatic
archive is created. Existing daemon upload bounds and retention still own artifact storage.

`--prepare-only` saves without starting. `run reconnect FILE` verifies host/caller/grant and resends
the exact saved request; it neither rereads files nor regenerates IDs. Changed canonical contents
conflict. Existing application and internal control/runtime receipts recover create/start and the
gap before the outer receipt. Protocol 2.13 requires coordinated clients and daemon; direct invocation
saved documents and replay remain unchanged. Blueprint, workspace, model and journal versions stay
unchanged. [ADR 0045](../../../../decisions/0045-supplied-run-inputs-and-recovery.md) owns these choices.

Start/reconnect return acceptance by default. `--wait` requires explicit `--timeout-secs`, prints the
recoverable identity first, then uses the existing bounded run observation. JSON emits a nonfinal
`run.prepared` record and one final result/error. Client exit/deadline leaves daemon work running;
cancellation remains separate and does not prove remote termination. Model selection stays at
runtime dispatch, and replay leaves accounting, retained uncertainty and child-run ownership there.

Model preparation now verifies and materializes selected direct inputs through the existing context
port and provider mapping. The task document is interpreted as instructions once. Execution exposed
an authoring omission: generated nodes lacked the adapter's `provider_metadata` output. The current
generator declares the full model output set. Earlier immutable definitions are not rewritten;
the maintained recipe and tests save definitions with the corrected generator before executing them.
