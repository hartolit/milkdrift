# P01 — Structured source, execution and shared authoring

Owner: one coordinated blueprint/runtime/control boundary with assigned consumer owners. Requires
P00 and approved P2/r4, N1/r4/NP4. Read [shared context](context.md),
[NP4](../notation-profile.md), [structure comparison](../../working/structure-comparison.md) and
[application reconstruction](../../working/application-reconstruction.md). This prompt is proposed,
not assigned. It replaces the old graph-correction phase and the conversion-gated writer transition
withdrawn under U19. New evidence can reopen the representation decision; implementation inconvenience
alone is not evidence that an accepted capability may be removed.

Implement blueprint-owned `WorkflowProgram`, stable-ID structured elements, result contracts,
`ProgramEditBatch` and pure validation/lowering as specified in NP4. New authoring source has explicit
clause order, Conditional result totality, Parallel completion/outcome/exports, fixed exact Call,
bounded Repeat and complete time/targeted decision waits. Control/data and containment are precise;
containment alone does not create a run, grant or mutable resource claim. Ordinary Task with full
TaskConfig is the only new external action representation. Collection bindings distinguish explicit
historical sources from an exact join receipt and preserve ordered outcomes/value references.

One checked `ExecutionPlan` boundary supports new source and exact legacy graph activation. The
legacy lowerer does not require tree decomposition to keep a revision running. Each revision has one
tagged authored source; retain existing bounded versioned graph construction/import/copy/mutation
operations and validation in the same blueprint owner. Structured source is the new default, not the
sole admitted source. Runtime remains the
only scheduler/attempt/effect engine; do not embed a legacy engine in a region leaf. Source-to-plan
maps preserve stable definition and occurrence identities. Runtime/context/authority/risk/publication/
inspection/reconciliation consume the shared checked representation rather than separately guessing
region ownership. New conditional result publication and occurrence completion commit atomically
with the run/workspace facts. Unselected arms supply no mandatory data; result availability does not
prove all physical obligations settled.

Prospective change freezes accepted prefix, selected clause, active occurrence pins and accepted
result interface. Compare pending descendants and dependencies by stable identity. Compatible future
work inside a selected arm can change without replaying completed investigation. Reinterpreting an
active occurrence's scope, already used result contract or protected agreement refuses. Changing source
for a later invocation can remain legal under FinishCurrentThenAdopt while that occurrence keeps its
old governing revision; do not add a blanket changed-active-node refusal. Current
agreements' task-only editable regions do not silently become permission to rewrite structure.

For newly accepted Program agreements, implement the separate v2 source-skeleton contract in NP4:
fixed named disjoint Task-only Sequence scopes, sealed external input bindings and output signatures,
exact allowed requirement envelopes, aggregate task/revision limits and effect policy. The protected
digest retains the entire outer program and each scope identity/interface while replacing only its
editable direct Task body/output implementation with a typed scope placeholder. Outside consumers
reference scope results, never private body IDs. Added/reordered/replaced Tasks and internal bindings
remain subject to ordinary authority and live reconciliation; nested control/calls/waits, verifier
replacement, scope movement or interface changes refuse. Mutable internal output implementation is
explicit v2 agreement semantics, not claimed equivalent to v1's protected boundary-edge identity.
Native graph agreements continue v1 validation; converted v1 uses the exact LegacyAgreementView.
No old agreement is automatically upgraded or weakened.

Move complete semantic editing to blueprint and authenticated prepare/validate/save/admission to
control. Protocol carries versioned complete source/edit DTOs; daemon translates authenticated requests.
Expose create/inspect/edit/validate/save/convert with exact base identity through the shared daemon;
CLI and independent JSON clients must use it. Two valid immutable successors of the same base remain
valid siblings. Layout has no semantic authority. Model-result admission in P04 will use this owner,

Migrate prompt-sequence's useful coding/review dialect to emit the source through the same owner;
retain CLI offline compilation and source-stage mapping. Migrate finite model-step convenience
commands to complete source edits. Remove daemon's private `ModelWorkflow` semantic ownership;
preserve existing graph convenience behavior by delegating version-specific construction/recognition
to pure shared blueprint helpers. Their exact shape/refusal contract remains; generic graph mutation
supports richer graphs. Remove new-source capability-reducer writers and
special external dispatch/risk/authority branches after legacy lowering maps their exact historical
source ordering/default requirement/context into ordinary task plans. Historical reader code is not
the only compatibility support: existing graph writes remain supported through the same owner.
Update examples, proposal construction, publication validation,
control risk and all real consumers in this unit.

Keep deterministic compilation for each old public command version, including convenience genesis.
A stored outer receipt replays directly, but a revision may have committed before that receipt:
retrying the same old request must recover the same graph revision, not compile Program under a new
default. New default convenience output requires a new command/version or explicit source-family
selection. Persisted request identity must not silently change meaning during upgrade.

## Supported data and upgrade

Preserve old immutable bytes/digests, command results, branch ordering/selections, task identities,
child pins, active/uncertain effects and account/resource facts. New protocol/definition/event shapes
have exact version readers. Old clients refuse unknown semantic versions before editing. New layouts
address stable source elements; obsolete legacy layout remains historical decoration, never a semantic
conversion oracle. Optional snapshots may be rebuilt only from intact accepted history.

Equivalent conversion must demonstrate ordering, activation, value visibility, result and agreement
correspondence. Live adoption separately checks preserved occurrences, accepted results/obligations,
current sequence and changed future frontier. Changed successors need not be wholly equivalent.
Refuse unproved conversion or cross-family adoption with element-specific reasons while keeping native
graph repair available. A pending-task edit must still work when an unrelated subgraph cannot be
converted. Native repair never creates fictional completed occurrences or forgets unknown work.
Carry exact selected proposal base through delta/risk/reconciliation; do not infer it from the first
sorted merge parent. Test merge-parent ordering distinct from selected base.

Apply the adoption plan's five-state matrix: closed history, reusable inactive definitions, unentered
future work, started/uncertain effects, and governed/protected work. No new grandfather registry or
source-family permission gate is needed. Preserve current versioned graph create/import/copy/edit
and their real refusals, including governed identity-bound copy and inherited-child agreement rules.
The program does not retire graph writes. A future separately reviewed deprecation must demonstrate
repair/reuse coverage, address clients and all accepted obligations, and obtain approval for residual
loss. Cancellation or separate work is not a passing substitute for prospective repair.

Gate new writes behind supported store/protocol version checks. A stopped supported store upgrade
retains old facts and exact receipt lookup; new events are not rewritten into old events for rollback.
An older writer must refuse the new generation. A pre-upgrade backup can be restored only after
accounting for accepted external work since it was taken; otherwise preserve the new store for recovery.
No live user's data conversion or destructive cleanup is authorized by this proposed phase.

fixtures, ordinary parallel/call examples and protected root methods with allowed Task-only future repair.

shape from checked source/plan plus complete origin correspondence and apply original v1 fingerprints/

graph where conversion refuses but a legitimate pending-task native repair succeeds and active identity
remains unchanged. Retain precise uncertainty recovery and agreement refusals. Refusing every

GraphNative validator/admission contract; diagnose known problematic topology without introducing a
blanket stricter rule that rejects a valid unrelated repair of an already accepted graph. Program
validates its own structured source. Crossed-All remains a separate stalled-shape diagnostic; no
general cross-scope token semantics or universal graph conversion is promised.

reconciliation, publication and branch source. An ancestor's actually accepted cancellation can justify
its descendant; a merely inactive branch, unrelated sibling or fabricated event cannot. Preserve
accepted history and exact replay. This is a required concrete P01 runtime repair, not a new scheduler,
graph retirement rule or invention of historical cancellation facts.

external input sources, scope signatures, requirement envelopes, verifier/effect identity or control
