# Product model and value account

The reviewed purpose is ongoing useful work with explicit authority, evidence and future change.
The source is the user's [selected original excerpts](../intent-source-excerpts.md), with origin,
standing and uncertainty tracked separately in the [intent register](../working/intent-register.md).
G1/r1, P1/r2 and P2 own the selected planning interpretations. Current vision and accepted ADRs are
implementation evidence and prior judgments, not independent user endorsements.

## Objects and relationships a user needs

| User-facing object/action | Meaning and relationship | What it must not imply |
| --- | --- | --- |
| Connection / owner | A route authenticated as a specific host, actor and grant; each owner retains its own work | A connection does not join a cluster, establish peer trust or combine permissions. |
| Goal / draft | Editable intent and a reviewable human/agent candidate | Prose or local draft state has no authority to execute. |
| Method / saved revision | Immutable reusable definition with exact inputs, outputs and constraints | Saving does not start work; editing creates a new revision. |
| Run / attempt / result | Accepted work, individual effect progress, and selected accepted evidence | Accepted, succeeded, verified and physically stopped are not synonyms. |
| Future change / proposal | A guarded prospective decision against the observed run and governing agreement | It cannot rewrite past evidence, switch an entered effect or lower protected acceptance silently. |
| Local call / eligible copy | Exact child pin at the workflow owner, or an independently editable revision where constraints permit | Remote readability alone allows neither local resolution nor removing identity-bound agreements. |
| Public service / invocation | Stable callable interface with its own admission, result and disclosure contract | Caller rights do not include private definition/history/editing; publication is not required for all reuse. |
| Direct operation | Capability work without a synthetic workflow | It does not bypass grants, accounts, constraints or uncertainty. |
| Managed installation / use / editing claim | Prepared generation, retained use protection and exclusive permission to alter it | Invocation completion or cancellation acknowledgment cannot prove physical quiescence. |
| Knowledge / study / promoted candidate | Selected evidence, frozen evaluation and a separate future-selection decision | Attractive model output or an inconclusive study cannot silently change accepted calls. |

The interface uses verbs that expose these consequences: Save, Run, Change future work, Use exact
revision, Make independent copy, Call service, Invoke directly, Inspect installation, Compare and
Promote. Common discovery may offer eligible choices, but each committing action names its owner,
meaning, inputs, target and authority. Direct context-specific routes remain available.

## Alternatives, losses and reversal conditions

The current-exposure alternative retains tested behavior with the smallest transition but leaves
some authoring awkwardness and cannot represent an ordinary shared exclusive continuation. Intent-led
authoring adds whole edits and targeted semantics at the existing owner. Canonical regions could
prevent malformed partial structure but must preserve current data/context access and future repair.
An executable UML/BPMN subset adds external-tool potential only after activation/data/cancellation,
authority, retained evidence and interoperability are defined and tested. The full independent
positions remain in Ada's and Bram's records; the comparison is not inferred from a committee vote.

The selected change replaces incomplete presentation/construction assumptions, not durable truth.
Layout stays presentation; unsupported semantics are refused rather than flattened. Historical
blueprint identities remain readable with their old meaning, while one current writer/runtime owns
new definitions. Exact requests, pending work, resource obligations and closed history survive or
receive an explicit supported drain/refusal path. An old binary cannot be promised safe rollback
after a new writer has accepted effects or data it cannot read.

The bounded choice remedy requires one selected arm, explicit normal exit, declared selected output
bindings and no hidden scope. Data from an arm cannot bypass the merge into a later required input.
Inner FirstSuccess/quorum may enable nonconflicting continuation while a losing writer still retains
holds/uncertainty. Failed/cancelled arms do not activate a fallback automatically. Compatible unentered
future repair remains possible; switching the recorded selection or rewriting consumed data refuses.
This is a proposed new contract, not a fact established by existing tests.

The main risk is preserving an awkward core behind ever more convenience rules. If real complete
editing cannot obey one public interpretation without special hidden workflows/compilers, reopen
P2 and compare the region alternative at the same demanding scenarios. The inverse risk is declaring
simplification successful by dropping difficult control, privacy, tool improvement or learning
outcomes. Neither fewer concepts nor fewer lines establishes success.
