# Product alternatives and meanings — P2/r2 selected planning interpretation

This integrates independent [Ada-P2/1](product-position-ada.md) and [BP1](product-position-bram.md)
after both were recorded. [P2](../../whiteboard/discussions/product-model/authoring-and-control.md)
owns the current recommendation; [G1](../../whiteboard/discussions/vision/remedial-purpose.md) and
[P1](../../whiteboard/discussions/product-model/reuse-service-and-placement.md) own upstream choices.
The comparisons below remain design reasoning, not measured usability.

## Actions and promises

| Action | Successful meaning | Refusal or interruption; neighboring consequence |
| --- | --- | --- |
| Prepare a goal/manual plan | An editable draft or agent proposal, with explicit owner and requested capabilities | Text cannot grant authority. Unknown operations or invalid base remain a draft/refusal, never scheduled work. |
| Save a method | Daemon validates an immutable revision and exact ancestry | Envelope/base mismatch refuses; valid same-parent edits may both save as divergent revisions. Explicit selection/comparison is deliberate; no mutable latest-head overwrite. Layout moves do not save new semantics. |
| Run with inputs | Owner durably accepts the exact request and freezes revision/input authority | Accepted is not completed. Recover the same request after lost reply; do not generate a new ID. |
| Inspect result | Authorized occurrence/attempt/evidence explain invocation, acceptance and final outcome | Missing/denied/unknown/expired are distinct. Public service result is not the private child's entire history. |
| Change future work | Control validates a proposal and runtime prospectively adopts the permitted portion | Completed/uncertain work is preserved. Changing required acceptance, target or authority requires a different authorized decision. |
| Reuse/copy/call | Exact reference, independent eligible definition, or public service invocation as P1 specifies | Readable foreign revision is not a local pin; governed copy can refuse; service call grants no internal edit rights. |
| Improve tools/resources | Managed owner accepts a specific prepared lifecycle change | Use/uncertain physical writers can block maintenance. Removing while preserving data is not release from management. |
| Learn and promote | Frozen evaluation supports an explicit future selection decision, including rejection/inconclusive | Candidate success cannot rewrite earlier evidence or silently change existing calls. Local evidence read is not permission to export it. |

## Complete candidate comparison

**C: direct exposure of existing owners.** A complete production interface for today's public
operations preserves tested boundaries with little data migration. Its strongest case is that most
execution mechanisms already have positive, refusal and restart coverage. Its real cost is asking
authors to express a practical action through multiple low-level graph/publication concepts. It
must explicitly refuse standard constructs it cannot express; a nicer screen cannot cure that.

**I: intent-led authoring with targeted semantic remedies.** This candidate combines complete
compound edits, exact operation consequences and source-backed improvements. It gains simpler
author decisions and supports existing difficult behavior. It adds maintained owner-side construction
rules and a genuine reconvergence change; therefore it is more than cosmetic relabeling. One
daemon validation/compilation path must serve Svelte, CLI/API and agents. P1's common discovery is
independent of whether typed nodes or regions become the canonical representation.

**R: canonical structured regions.** Sequence, exclusive choice, parallel, repetition and calls
become complete owned definition regions; graph edges are projections. This can prevent invalid
partial structured edits and remove repeated port wiring. It risks narrowing graphs, cross-region
data/context access and prospective changes. Its transition must preserve current accepted histories,
pins, commands and unknown effects without maintaining a second permanent scheduler. It remains a
credible alternative if I cannot give complete actions without many exceptions.

**S: standard executable foundation.** A declared UML Activity or BPMN subset becomes the semantic
contract, with explicit Milkdrift extensions. This offers meaningful external-tool interoperability
if the user wants that outcome. It changes activation, cancellation and multiple-token assumptions;
schemas alone cannot prove equivalence. Authority, resource holds, service identities and live
revision adoption still need owned contracts. U08 prefers principles but does not establish a
full import/export requirement or measured model advantage.

I is selected for the planning program after actual combined review because current owners serve
concrete outcomes and the identified defects/gaps have bounded owners. It remains subject to user
approval and early real use. R/S are not rejected on code size, sunk cost or an assumption that present vision
must win. E07 already forces I to change an executable boundary rather than merely expose it.

## Value and loss account

| Outcomes | I versus C | What R/S must preserve or explicitly negotiate |
| --- | --- | --- |
| V01/V02 operation/authoring | Goal, graph and outline share validated submissions; more maintained forms and construction operations | Generic tools/files and expressive human/agent plans; no fake reduced editor. |
| V03/V11 adaptation/control | Existing prospective evidence with clearer permitted-region and obligation distinction | Authority inheritance, fixed agreement, account ceilings and uncertainty during definition transition. |
| V04/V05 reuse/services | Shared discovery, explicit reference/copy/public-call action and honest denied expansion | Existing pins/copy limits/service identities/public-only results without mandatory publication for all reuse. |
| V06/V08 owners/direct work | One client with isolated connections; direct calls stay direct | Independent workflow owners and execution-only hosts without a central account/broker or compulsory process wrapper. |
| V07/V12 resources/lifetimes | Resource discovery/inspection remedies expose existing lifecycle; no claimed detach | Durable generation/holds, quiescent editing and preserved files; external operator ownership needs a separate contract. |
| V09 control/data | Source-backed symbols and R-C01 planned reconvergence remove one demonstrated authoring restriction | Waiting versus transforming, branch-local mutable state, bounded repetition, exact signals and asynchronous cancellation. |
| V10 learning | Complete selection/comparison/promotion interactions with negative outcomes visible | Fixed held-out declarations, known evidence scope, independent variants and separate promotion authority. |

No currently useful behavior is selected for deletion. This is not a promise of zero transition
cost: protocol/definition changes may require coordinated upgrade and old binaries must refuse new
formats. Browser users gain real interaction but take on origin/TLS provisioning and ephemeral
credential limitations. Optional third-host relay, unmanaged release and standards interchange are
separate decision branches, not concealed near-term deliverables.

The same hard case challenges all candidates: A owns an evolving project, B offers a private
method, C supplies a tool; a child needs an already-held working area; authority changes while a
review fails; the operator closes the client and resumes. C must expose these distinctions without
manual hidden reconstruction; I must not emulate them in UI state; R must preserve their scopes
through region replacement; S must define extensions and cancellation tokens without pretending
an end symbol proves physical stop. Final acceptance must demonstrate useful progress and refusal
together, not separate menu screenshots.
