## Reconstructing one demanding S28/S21 path

This is a proposed acceptance trace, not a claim that all its parts currently work. Its progress
and refusal steps deliberately share the same accepted records and resources.

1. **Adopt and connect.** The user approves the finite outcomes, initial deployment and custody
   choice. P00 records exact decision revisions, canonical changes and P09's final-gate schedule.
   P01 serves the actual static client under an operator's approved CSP endpoint set; A, B and C
   each explicitly allow the client origin. Remote transport uses configured HTTPS termination.
   Version/authority negotiation binds each session to its stable host, actor and grant. A URL
   outside the set gets a setup explanation. An unreachable A leaves authorized B/C views usable.
   An endpoint replacement cannot inherit A's draft/cursor/request. Bearer delivery still trusts
   the chosen origin before authenticated host discovery; this is not a cryptographic preflight.
2. **Turn a fragmented brief into inspectable work.** On workflow owner A, select bounded source
   artifacts/context under actual read/transfer rights. P04's R-FE02 uses a maintained authorized
   model/controller consumer to propose a structured candidate, or proves the existing consumer
   sufficient. The candidate is untrusted until daemon validation. Independent analyst branches
   receive declared context and retain their disagreements; no shared mutable workspace is inferred
   from a common UI panel. Wrong capability/authority or malformed plan remains a useful refusal
   with editable draft, not an effect. P02's simpler author/run path remains usable throughout.
3. **Save the complete method.** P04 supports graph, outline and machine authoring through one
   construction owner. Save immutable revision R on A with a governed bounded account, ordered
   choice, parallel investigation, explicit result selection and shared review. Exact local reuse
   pins a revision present at A; it does not pin a definition merely readable at B. The proposed
   selected merge forwards each declared output from the chosen arm; a data wire directly from an
   unselected arm to the reviewer refuses. Saving a method and starting a run are separate commits.
   If another author saves a different valid edit from the same immutable base, both may exist as
   siblings. The UI compares their ancestry and selects an exact revision; a genuinely mismatched
   submitted base guard refuses, but a second author's existence is not itself a current-head lock.
4. **Accept exact work under realistic rights.** P01/P02 retain/export the exact start before
   sending once. Let A's selected arm fork a call to B's private method and a granted tool at C.
   A has configured peer relationships for those workflow-origin calls; adding B/C to the browser
   does not create them. An invoke-only B caller can inspect declared public progress/output but
   cannot read its child graph. P05 supplies a qualified internal link only if separate current
   internal read permission is later granted, and removes cached private metadata if it is lost.
   C may be execution-only; direct C operations also work independently without synthetic runs.
5. **Make B's exact child progress.** B accepts an exact generation/request and stores the planned
   internal association before child creation. Give B one constrained serving worker. Its waiting
   publication wrapper yields that worker while retaining generation/resource protection. Valid
   no-entry proof and exact parent/child claims allow B's physical child to acquire editing; a
   conflicting maintenance request refuses, while unrelated resources remain usable. A needs enough
   own capacity for the intended fork; no global single-worker claim is made. E06 supports the
   current wrapper/child composition, while P06 must test this full interface trace.
6. **Continue a selected result without erasing the loser.** C supplies accepted result x; A's
   FirstSuccess/quorum join satisfies while B's losing child has entered and lost its stop report.
   Its cancellation request is real, but no proof of stop. The selected merge may record x and
   one shared continuation. The read-only reviewer can enter only with remaining allowance and
   nonconflicting authority/resources. B's holds/unknown reservations remain. Restart A between
   selected-result and continuation commit: P04 must recover the same occurrence/provenance and
   never choose the unselected arm or enter the reviewer twice. P06/P09 compose that proof with
   B's retained writer rather than treating separate green menu tests as equivalent.
7. **Respond to a failed review and a changed plan.** Keep the failed verification under its actual
   governing revision. An authorized proposal replaces an unentered reviewer/investigation step
   inside the chosen arm, preserving consumed x, selected route and protected obligations. P04/P06
   must show this positive prospective repair. Switching the chosen arm, changing the entered
   writer's target or weakening the protected verifier refuses. A human wait is durable; browser
   timers and proposal overlays cannot advance it. The plan can keep evolving within the inherited
   account; a new label/revision/child does not replenish reserved allowance.
8. **Lose a session, an owner and some rights.** Close the tab after submission but before receipt;
   reload and authenticate before recovering the retained exact record. If A is unavailable, a
   connected authorized B reader can inspect B's accepted invocation/resource; it cannot continue
   A's workflow ownership or synthesize A's missed history. A new workflow grant may permit known-run
   inspection while exact saved-start replay still refuses. Direct serving has its own explicit
   retained-request recovery under current Inspect permission and stored original basis. Denied or
   missing reads are not proof of no effect; no replacement request/host is automatic. P01/P02/P05
   own these paths and show which operator/right is required next.
9. **Resolve resource control honestly.** A full ordinary recovery store leaves the reserved
   control capacity available; if even that/storage fails, exact export or a current-authority
   native control path remains explicit. Cancellation does not erase unknown work. An authorized
   operator inspects and resolves/fences the exact B use with current claims; maintenance can then
   proceed only when its actual conditions hold. Physical safety/progress can be established while
   the old operation outcome or usage remains uncertain. P06 cannot mark an old result successful
   to clear a blocker, and rollback cannot restore an old database over a surviving writer.
10. **Learn without rewriting the investigation.** P07 selects allowed evidence and declares held-out
    evaluation before candidate proposal. R-FE01 lets a fresh browser find the exact failed or
    inconclusive study through the existing receipt owner. A candidate that changes acceptance,
    leaks private evidence or reuses source/training material as its held-out basis must fail the
    appropriate check. An eligible different candidate may be separately promoted for future use;
    current calls remain pinned. Two projects can use immutable lessons while their mutable files,
    inputs and evaluation stay independent. A negative study is a valid completed study.
11. **Qualify the product, not just the mechanism.** P08 has the actual user enact this compound
    project, explain rights/recovery and introduce an independent counterexample. Agents performing
    capabilities cannot secretly carry the whole coordination outside Milkdrift. If S28 needs
    another real public primitive, its current phase repairs/reopens the exact decision; no empty
    “research node” completes it. P09 runs final Rust/frontend/real-daemon evidence after all selected
    remedies and authentic checkpoints, preserving source/binary/environment/test identities and
    explicitly unqualified physical/network/model claims.

The trace offers a permitted path at every major refusal: editable rejected candidate, independent
connection, public service result, compatible future repair, current-authority inspection, exact
resource resolution or bounded control fallback. It does not promise progress past a genuinely
unavailable owner, insufficient authority, exhausted allowance or unresolved external writer.

## Primary-source checks that constrain the reconstruction

- `RuntimeService::try_satisfy_join` and `add_ready_successors` in
  [completion.rs](../../../../../crates/runtime/src/engine/completion.rs) distinguish join
  satisfaction/selected source readiness from physical completion. `add_ready_successors` uses
  current occurrence/scope, route and predecessor readiness before `NodeBecameEligible`; it is not
  an external-entry transaction. This is why PR-C1 matters. The new merge is still unimplemented.
- [Terminal deferral](../../../../../crates/runtime/tests/structured_runtime/lifecycle/cancellation.rs)
  keeps a run nonterminal while an already-dispatched join loser remains active. The managed
  `release`/`transfer` checks in [uses.rs](../../../../../adapters/redb-store/src/managed/uses.rs)
  retain quiescence and exact accepted lineage requirements; they distinguish the wrapper's
  `NoExternalEntry` from a physical parent needing a fresh entry epoch. E06 tests positive child
  transfer and lost stop proof, supporting PR-C2 without proving the new combined graph.
- [SavedRunRequest](../../../../../crates/control-client/src/saved_run.rs) requires exact current
  `AuthorityRead`, and [command_fingerprint](../../../../../apps/daemon/src/host/receipts.rs)
  binds actor/grant identity/revision/digest. In contrast,
  [invoke_client](../../../../../crates/capability-host/src/serving/direct.rs) looks up a retained
  actor-scoped serving request, requires current Inspect, takes its stored authorization basis
  and compares the rebuilt exact digest. Thus P02's workflow recovery and P05's direct recovery
  cannot be one blanket grant-change policy.
- [HTTP routing](../../../../../apps/daemon/src/http.rs) and
  [bearer extraction](../../../../../apps/daemon/src/http/response.rs) plus E04 support absent
  current CORS and authenticated bootstrap. A new client/CORS/HTTPS/CSP path requires its actual
  new browser lane; no Rust-native test closes that prerequisite.
- [Trial dependency exercise](review-method-trial.md#hypothetical-dependency-exercise) and the
  [fresh-read hypothetical sections](trial-fresh-read.md#hypothetical-dependency-change-a-the-caller-gains-internal-read-permission)
  show exactly what the early hypothetical changed. Source-route ambiguity about execution-only
  relay does not substitute for that historical experiment.

### S28 through the selected combination

1. **Accept the ongoing work before a generated method exists.** Exact goal/source selection,
   allowed scope/actions, approval policy and finite ceilings enter `WorkCommitment` with its
   account and first pending action atomically. Explicit versioned commitment authority prevents
   an old wildcard grant from silently authorizing a new control family. Frozen commitment basis
   is not a fabricated `ExecutionAuthorityBasis` with an invented root run.
2. **Make and use a real method.** Control prepares the bounded provenance-bearing packet from
   actual allowed sources/catalog/frontier/remaining allowance. A normal planning run is created
   and account-bound in the same transaction, then started by its exact retained command. Actual
   model output/context/invocation are authenticated. Blueprint validates/lowers the complete new
   structured source; control saves it, obtains ordinary required approval, then associates real
   work under the same account. No evidence driver supplies the accepted mutation or provenance.
3. **Assess criticism while work is nonterminal.** The commitment observes actual owner facts and
   may pause the affected target without closing its own planning gate. A fresh context receives
   exact earlier evidence, dissent and allowed prospective frontier. The outcome may retain the
   original result, investigate, revise, escalate or stop. A critic assertion is retained as an
   assertion; it does not become an instruction or accepted success/failure truth.
4. **Apply only permitted future change.** Completed investigation, accepted selected arm and
   consumed values remain fixed. Blueprint/control/reconciliation use one checked plan and exact
   current sequence. Compatible pending work may change; a concurrently changed target yields
   a retained stale refusal. An inherited governed child or proposed structural agreement change
   cannot use the ordinary Task-prefix adaptation grant. Separate authorized agreement/new work
   or escalation is the real route; an approval overlay cannot make it legal retroactively.
5. **Recover the actual accepted action.** Persist exact create/start/propose/apply/resume material
   before calling its owner. If the proposal committed but reporting failed, recover its same
   receipt; do not call the model again or compile different bytes under the old key. All planner,
   critic and ordinary local work consumes the commitment account. Published/private work keeps
   its actual service account and attributable outer reservation, not fictitious access to a
   private balance. Existing independently entered work cannot be swept into a fresh allowance.
6. **Intervene and stop honestly.** Policy successors use PR-E3's exact action disposition and
   original ceilings. Closing the local gate does not erase an admitted local effect or B's
   accepted serving operation. Retain holds/unknown usage and expose the actual owner resolution
   path. No-progress/round/time exhaustion produces an explicit stop/escalation with unsettled
