# Early substantive trial — T1

The actual question is the relationship between reuse, restricted invocation and remote execution.
U07 both proposes and doubts a remote method bridge, while source has several working routes.
It can expose a false premise with downstream authority/UI consequences; it is not a terminology quiz.

Assessment was fixed by the supplied [trial guide](../review-method-trial.md) and independent
[Ada](trial-ada.md)/[Bram](trial-bram.md) predictions before observations. We checked source versus
interpretation, factual versus value disagreement, successful and interrupted paths, alternatives,
fresh-reader reconstruction and limited dependency changes.

Independent intake preceded synthesis. Ada preferred common discovery; Bram preferred distinct
entry actions. After reading each other's positions, each appended an actual response. Both keep
their strongest objection: a chooser can preserve contracts yet confuse control expectations.
The coordinator's combined candidate is reviewed as a new proposal, not inherited consensus.

[E01–E03](observations.md) exercised ordinary authoring/reuse/repair, direct and delegated hosting,
invoke-only results, publication retirement and lost boundary commits. They support distinct
current execution contracts and disprove universal publication as a description of current remote
execution. They do not decide human comprehension or prove publication is never a useful default.
The local-subworkflow permission prediction is source-modeled, not a newly executed author-without-
publication-grant test. Missing proof remains explicit.

Cyra, who did not author either position, reconstructed the choice and found actual missing scope:
remote readability does not supply a local revision; identity-bound agreements can refuse copy;
role removal must account for live obligations. [Fresh-read record](trial-fresh-read.md) preserves
that review. P1 changed from candidate r1 to [r2](../../whiteboard/discussions/product-model/reuse-service-and-placement.md).
Product action eligibility, call expansion, authoring API assumptions and adoption tests needed
rechecking; direct process semantics, exact receipts and unrelated managed evidence did not.

## Hypothetical dependency exercise

This is hypothetical, not changed source or an observed defect. If a service customer gains internal
read rights, inspection/expansion and cache scope change; service identity, accepted generation,
invoke authority, history owner and replay do not. If the target is execution-only, local definition
creation/publication must refuse or require explicit workflow-owner selection; ordinary direct
operations remain eligible. No silent role switch or relocation follows. Cyra's independent account
names the same limited dependencies and separately catches actual source qualifications.

## Method result and correction

The method supports scaling the planning review with explicit conditions: it located original
uncertainty, preserved a real value disagreement, used current execution evidence without claiming
usability, and changed dependent rules after a fresh reader found missing facts. Independence is
limited: readers used the same excerpt selection and repository; Cyra authored source evidence.
No complete original conversation or human usability study was available.

The concrete packet correction is to qualify every reuse choice by where its revision exists,
whether identity permits copying, and whether the target owns workflow execution. No new global
practice is adopted. Later reviews must trace the entire public command path before declaring a
missing feature: Bram's preliminary layout-digest gap was withdrawn after finding daemon receipt
normalization, a real example of a type declaration misleading a partial trace.

02 permits 03–06 comparisons on G1/r1 and P1/r2. It does not certify the unimplemented hybrid or
erase the separate-routes alternative. S28 and final prompt review carry this case forward.
