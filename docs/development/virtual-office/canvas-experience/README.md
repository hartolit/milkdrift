# Canvas experience side sprint

**Prepared, not assigned — 2026-10-23.** The user requested a judgment on design readiness, one
holistic frontend design and a side sprint alongside the unfinished main sprint. This packet
performs that planning. It authorizes no production implementation, deployment or spending.

## Readiness judgment and selected scope

The discussion phase is sufficient for this bounded implementation. The
[holistic design, ADR 0052](../../../decisions/0052-canvas-authoring-and-method-experience.md), selects
one experience from the debates and owns its durable decisions. Actual usability is unverified;
early working review and repair are part of delivery. Further abstract debate is not a prerequisite
for implementing this scope, but evidence can reopen a specific choice.

| Previously open choice | Selected disposition |
| --- | --- |
| Empty placement, model choice and unfinished wires | Preserve blank placement; a visible usual model supplies real ports where selected; unfinished wires retain intent but cannot execute. |
| Useful work beside incomplete ideas | Deliberate visible Run scope, including reviewed necessary predecessors; no automatic ready subset. |
| Sustainable saved authoring | Bounded conditional snapshots with current-state reconciliation; exact command replay remains separate for deliberate admission/library changes. |
| Backend friction | Repair pause/recovery/contention; distinguish data and order; stable output ceilings; meaningful authoring guards and local typed issues. |
| Method definition and use | Visual scratch authoring and clean-selection extraction; latest saved content when root inputs/start conditions are ready; default final exports wait for required copied work. |
| Method adaptation and outcomes | Edit eligible local future copies; adaptive continuation belongs to the workflow. Execution success is not quality approval. |
| Larger extensions | Defer early snapshot customization, arbitrary method-owned descendants, branch-specific human-decision gates and automatic model substitution. Preserve ordinary existing capabilities. |

The smaller alternatives and strongest objections remain in the linked whiteboard records. These
are selected planning defaults, not claims that the user has observed and accepted them. There is
no missing product choice that an implementer must guess to deliver this finite scope. If a selected
rule fails the required journey, repair its owner and reconcile the design rather than stacking a
client workaround over it.

## Usable outcome

A person opens a workflow in a daemon → project → workflow tree, arranges blank tasks, connects
context/results and defines them in a right inspector without leaving the canvas. Unfinished work
survives reload and another authorized client. Run admits only the deliberately reviewed scope.
The daemon continues while the client is closed; return reveals real progress, results and repair
choices. A useful selected procedure can become a method, be reused with different inputs, follow
compatible saved improvements until activation and produce inspectable local copies.

The frontend remains Svelte over public daemon operations. Existing Rust owners perform semantic
construction, authority, admission, execution and recovery. Preserve the real logo and established
visual direction while removing competing navigation and form-based authoring. No separate graph
store, method scheduler, universal transaction framework or mock product surface is a deliverable.

## Combined acceptance and preservation

Use the same ordinary and demanding cases throughout the prompts:

- Place two blank tasks without opening an editor; connect a useful source/result; define them in
  place and obtain real input-dependent output. Create a second workflow under a populated project.
- Leave an unrelated blank idea while deliberately running a complete chain. Include an accepted
  predecessor with an unapplied edit and a race with its start; preserve the candidate and meaning.
- Reconnect from another authorized client to unfinished authoring and actual admitted state. Race
  conditional checkpoints, lose Run replies, change actor/daemon and exhaust capacity truthfully.
- Pause before entry, restart while paused and resume without failure/duplicate entry. Let one task
  wait for project access while unrelated work progresses; retain uncertain writers' protection.
- Extract a method without copying accidental failure history/private content; reuse it for a
  different brief. Edit compatible content while a use waits, repair a changed interface locally,
  interrupt accepted expansion, then inspect exact origins and alter a genuinely unstarted copy.
- Inspect an early result while its export release waits for review. A successful negative critique
  remains a critique, not approval. Ordinary bounded workflow continuation stays available.

These are acceptance obligations, not executed evidence. Use production owners for decisions;
controlled Rust endpoints may supply inputs and documented faults but never expand methods or
schedule recovery for the daemon. No paid provider or new external service is authorized here.

Inspect real Git/store/service context before implementation. Preserve current supported records,
frozen starts, canonical receipts, project files and protected artifacts. New source compatibility
must be demonstrated against actual supported fixtures/stores; neither resetting roots nor claiming
universal historical compatibility is acceptable. Unsupported old formats refuse before mutation.
Use additive or explicit checked adoption for the current format and coordinated client/schema
updates. Layout/draft retention cannot consume reserved stop/settlement capacity.
