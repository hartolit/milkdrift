## Delivered behavior

Execution-only hosting constructs storage, authority, registry, adapter lifecycle and serving workers
without a workflow runtime, control service or workflow workers. Both roles expose useful direct
process and fresh-model calls, bounded public input upload, artifact download, discovery, saved
request preparation/submission, lookup, inspection, paginated wait and cancellation. See the
[maintained operator recipe](../../../../../examples/operator/README.md#independent-execution).
Upload quotas and exact invocation/upload replay survive restart. Direct continuation is refused.
The maintained execution-only grant permits restricted uploads and adapter outputs, and does not
require a workflow lineage for direct calls. The public process/upload/restart regression loads this
grant from the maintained TOML, rather than using an administrator grant.

An origin workflow can invoke the same process/model operations on a second execution-only daemon.
The origin freezes and stages authorized artifact inputs and the causal manifest against the final
delegated request. Returned artifacts retain authenticated foreign provenance. Controlled requests
bind their existing origin reservation to enforced serving limits; imported bytes charge that
reservation atomically. Uncertain execution retains the complete unconsumed allowance across
restart. It is not terminal settlement, and does not authorize replacement entry.

Role removal refuses active workflow runs, leases or unresolved controller accounts. Closed history
remains available through offline inspection. A changed installation identity and unsupported store
generation refuse without rewriting history. Startup reclaims interrupted client uploads before
admission. Partial worker startup joins created threads; shutdown runs adapter cleanup in both roles
and reports unresolved ownership under the existing deadline policy.

## Canonical ownership and compatibility

- `crates/capability-host/src/serving/` owns acceptance, prepared entry, workers, cancellation,
  recovery, observations and the ordinary artifact bridge. Peer HTTP owns transport and origin
  registration/transfer. No peer-http compatibility re-export or parallel executor remains.
- Registry preparation and one-shot entry are shared. Runtime keeps the atomic local entry/account
  journal. The serving ledger is used for direct/incoming work, not duplicated local attempts.
  Ordinary builds no longer expose unprepared `execute_exact` helpers. Fixture helpers use
  preparation behind `test-support`; binding entered serving context is private.
- Process preparation freezes materialization, arguments, stdin, environment and secrets before
  durable entry; executable identity is rechecked before spawn. Model selection explicitly handles
  workflow manifests or direct inputs, including nested reference refusal and fresh-only direct use.
- Workspace owns `ArtifactOwner` and producer meaning. Direct/peer outputs no longer fabricate runs.
  Client inputs, peer inputs, host invocations and transfers use the ordinary publication owner,
  quotas, integrity and cleanup. `PeerCoreArtifactStore` and old HTTP-owned lifecycle modules are gone.
- Serving identity includes host, authenticated realm and principal. Client credentials cannot claim
  peer/workflow authorization; delegation cannot bypass origin restrictions. Accepted authority is
  retained while current authority is rechecked for entry and protected reads, including archival.

Exact versions: internal store 17; physical schema 12; artifact publication/accounting 3; hot serving
record 4; tombstone 2; serving digest domain v2; daemon configuration 10; control protocol 2.8; peer
protocol 1.4. Earlier generations are refused, without migration or authority inferred from missing
fields. Unchanged workflow/history readers retain their documented policies. The compatibility

[architecture](../../../../architecture.md), and [status](../../../../product/status.md).
