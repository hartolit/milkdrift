## Review corrections

- A declaration now names the held-out input field and returned candidate field. The observation
  reader checks those exact fields; a passed verifier cannot qualify a different returned product.
  Different artifact identities containing identical input bytes do not count as distinct cases.
- Eligibility requires the serving owner's successful public completion as well as the internal
  run's success. Duration includes public delivery. Missing completion, missing returned artifacts,
  incomplete history and unsettled usage remain inconclusive. Recorded authority refusals prevent
  eligibility. Current target protection must match the declared ordered checks.
- Promotion receipts retain a compact reference to the publication owner's committed method. This
  removes the large duplicated method document that could exceed the learning response limit after
  publication had already committed. Automatic promotion also retains its exact policy reference.
- Prospective authority for an unnamed worker checks a current registered implementation within
  the service grant, independently of temporary health or occupied permits. Scheduling and entry
  still enforce availability, capacity and current authority. A real host/runtime regression first
  reproduced the refused child start, then passed while proving that an unhealthy worker never ran.
  Publication no longer validates against a superseded registry generation.
- The maintained driver accepts a service port base for independent studies. Host operations docs
  explain that subordinate UID/GID allocations cover all concurrent workers, services and verifier
  containers for the Linux account; 131,072 IDs provide two private 65,536-ID mappings.

The supplied implementation's other boundary corrections were reviewed too: managed reference
inputs use the authorized bounded reader; catalog fingerprints retain meaningful availability and
contract changes while ignoring diagnostic refreshes; daemon shutdown releases the managed owner
with idle HTTP handles still alive. Publication tests preserve active calls during replacement and
reopen after failures before and after the publication commit. Rust owns all maintained tools,
fixtures and applications.
