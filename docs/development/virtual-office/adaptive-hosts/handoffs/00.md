model-generation and configuration-provenance topics remain unchanged.

Four accepted ADRs own the durable decisions, not this handoff:

- [0038](../../../../decisions/0038-independent-host-execution.md): typed origin separate from
  transport, shared prepared mechanics, runtime-only local history, generalized serving acceptance,
  explicit direct selection, actual producer/account identities and targeted allowance transfer.
- [0039](../../../../decisions/0039-managed-resource-ownership.md): resource records outlive
  operations; exact guarded intent precedes platform changes; lifetime holds differ from editing
  claims; explicit parent/child handoff requires proof that the previous writer has stopped.
- [0040](../../../../decisions/0040-protected-adaptive-methods.md): blueprint-owned immutable
  agreements, scoped preauthorized changes, separate verifier trust and exact candidate evidence,
  effect checks below every caller, ordinary proposal/evaluation/promotion owners.
- [0041](../../../../decisions/0041-published-method-invocation.md): starting method plus adaptation
  policy, constrained service identity, stable create/start command association, durable pending
  continuation, inherited accounting and no duplicate local attempt journal.

Runtime owns local acceptance, final entry/account transaction, artifacts' workflow causes,
cancellation and recovery. The generalized serving owner owns those facts for direct/remote
operations, with the shared host preparing exact requests. Resource owner retains platform identity,
use and removal facts independently. Control owns publication and the association to the one real
internal run through runtime commands. Authentication prevents delegated work being relabelled
direct; invoke-only service callers receive a bounded operation without raw internal grant union.

## Shared application and evaluation decision

The sole maintained specification is [Slotbook](../../../../guides/adaptive-method-example.md).
It fixes the source workshop brief and its prototype-versus-authenticated/durable contradiction;
seeded failure is anonymous writes plus volatile bookings, separately labelled from live observations.
An operator-owned pinned verifier checks public privacy, authenticated mutations, capacity/intervals,
restart persistence, cancellation cutoff and exact deployed candidate/configuration/target.
Repair/learning cannot change those checks, verifier, target, agreement or limits.

The editable method permits investigation and future implementation/repair changes within protected
interfaces. Adding a planning responsibility is a hypothesis, not the required answer. The proposal
must cite the actual source run's decisions, contradictions, failures and repair. Evaluation uses
`loan-a`, `loan-b`, `class-a`, `class-b`, isolated from the proposal context and evaluated under the
same baseline/candidate tools and limits. All four candidate cases must pass; no pair may regress;
the total must save at least two repair rounds. The specification defines rejection/inconclusive
cases, comparable envelopes and separate final loan/class variant runs. No positive model-learning
result is required or claimed by this assignment.

proposal → fixed evaluation declaration and four paired runs → promotion/rejection/inconclusive
decision → selected exact publication and independent variants. Raw logs belong under ignored

## Nested resource use and integrated test allocation

Use explicit editing handoff under ADR 0039. Lifetime holds stay with the parent and accepted child;
mutation belongs to at most one. Parent suspension and physical writer quiescence precede a resource
transaction comparing exact accepted link, resource/claim generation and inherited authority and
transferring the claim. 0041's stable command association can identify the child before creation;
child writes require both valid linkage and committed transfer. Runtime remains the suspension/run
event owner; persistence/redb atomically own resource claim and handoff changes, not another scheduler.

On interruption, recover the same association/claim generation with admission closed. Unknown writer
state blocks parent writes/removal. Child terminal alone, lease expiry, timeout and cancellation
acknowledgement do not prove stop. Adapter/supervisor evidence of quiescence permits settling child
use and guarded parent reacquisition; a cancelled parent never resumes. Existing authorized
command/read and retained-work resolution patterns gain resource blocker inspection/resolution in
02. An authorized disruption must physically fence before reuse and keep the old effect uncertain.

02 implements resource transitions/fault tests against accepted execution relationships. 04 implements
the integrated published parent/child association and **one execution worker, same working area**
test: child makes progress while parent waits; parent/conflicting writes and removal/replacement
refuse; other resources progress; proven child completion returns editing with no duplicate or
leaked hold. Interrupt at handoff and active child, restart and cancel, then inspect and resolve
through normal authority. 06 reruns this product-binary case. This design does not claim a current
deadlock was found or that the test has run. Prompts 02, 04 and 06 now carry it explicitly.
