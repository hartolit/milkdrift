## Result and ownership

A governed method is callable through the ordinary capability path by a local workflow, a direct
invoke-only client, or a peer. Control validates and publishes its exact starting revision,
agreement, finite input/output contract, configured service grant and internal allowance. The
registry advertises the implementation; its capacity reservation precedes the publication commit.
Replacement creates a consecutive generation. Retirement prevents new selection and retains
accepted calls. Restoration cannot replace a missing or unauthorized generation with a newer one.

The [guide](../../../../guides/published-methods.md) owns configuration and commands. Current product
facts and versions belong to [status](../../../../product/status.md), and
[ADR 0041](../../../../decisions/0041-published-method-invocation.md) owns the design. Execution-only
hosts refuse local publication configuration and retained implementations; they can consume remote
capabilities without constructing a provider workflow engine.

For local calls, `PublishedInvocationPlanned` in the parent attempt's journal owns the association.
For direct/peer calls, the existing serving record owns it. Each saves the exact public request,
publication, service basis, allowance, child identity and canonical create/start commands before
internal creation. Runtime owns three replayable transactions:

1. Create the exact child at sequence zero with its input state and authorized creation receipt.
2. Append `PublishedRunBound` and establish its cumulative account from the saved allowance.
3. Start that child with the saved command expecting sequence two, establishing the fixed service
   execution authority and agreement acceptance.

Lost replies replay those receipts. Cancellation has one stable child command. Terminal result
recovery reads the same child, and failed result copying or recording leaves the public operation
pending. Local calls gain no second serving ledger. The pending index and managed child index point
back to their authoritative association rather than becoming independent journals.

Control implements the host-owned continuation port. Runtime and serving advance bounded pages,
releasing worker slots while retaining exact generation and resource ownership. Internal work uses
the existing scheduler. No per-invocation thread, synchronous child wait, CLI subprocess wrapper,
second graph store or second workflow engine was retained.

## Authority, accounting and resource transactions

The configured service grant permits only the reviewed internal workflow, capabilities, resources
and result reads. It is independent of the caller's invocation grant. Public inputs are finite JSON
choices or readable exact artifacts; accepted terminal fields alone become public outputs. Copies
are restricted. The receipt-scoped output route grants no general artifact, workspace, run, secret
or administration access. Authorized editors use ordinary run inspection and prospective proposals.

Internal final entry checks the enclosing public call before and after adapter preparation, as well
as current service authority. Runtime checks local caller chains; the serving owner checks incoming
client/peer records and policy. Unavailable authority fails closed. Cancellation, expiry and
revocation prevent further entry without claiming that previously entered work has stopped.

The method account survives ordinary descendants, revisions and restart. A controlled caller first
reserves the full supported internal envelope, then settles attributable nested use once. Public
copies consume their own attributable bytes. Unknown use retains the reservation. Service authority
and host/relationship ceilings apply independently; there is no new service-wide spending ledger.

Managed acceptance acquires a lifetime hold in the same transaction as its caller's acceptance.
The wrapper's final entry records `NoExternalEntry` against that exact association. Child scheduling
compares the saved association, service grant and resource generation, advances the parent claim,
suspends parent editing, and gives the child the sole writer. An ordinary child must prove physical
stop before terminal settlement returns editing; the next child compares the new claim. Cancellation
acknowledgement, an expired lease and a missing process report cannot manufacture stop evidence.
Uncertain child use retains both lifetime holds and blocks parent writes and destructive maintenance.

## Review corrections

- A descendant previously checked only its own nesting limit. `PublicationAncestor` now retains
  every accepted ceiling in local associations and peer delegation. A more permissive descendant
  cannot extend a stricter ancestor, and missing ceiling metadata is refused.
- A public invocation could expire or be cancelled during internal preparation, after its last
  continuation poll. Final entry now rechecks that invocation. The regression changes it inside
  preparation and requires zero process entries. The serving attachment is weak and is released
  after clean shutdown so replacement policy uses its actual current owner.
- The qualification helper wrote Python bytecode into the maintained example and broke the
  repository inventory contract. Its import now suppresses bytecode generation. The first added
  physical handoff observation was also moved past the definition's explicit repair wait.
- The handoff, current status, publication schema inventory, operator limits and evidence were
  completed. Public-copy documentation now states restricted classification rather than promising
  identical sensitivity labels.
- Publication operations now use their composed host rather than accepting a second host argument.
  The serving continuation pump is private to its existing maintenance owner. These remove unused
  choices without adding a registry or dispatch abstraction.
- Cancellation after a lost creation reply could leave the caller stuck because the child had no
  account and cancellation required an agreement that only start accepts. Cleanup now verifies the
  existing create receipt, completes the saved binding/account and cancels without starting.
  Governed runs cancelled before start do not manufacture agreement or execution acceptance.
  The same regression covers an editor cancelling the partial child directly; recovery appends its
  missing association without altering the already recorded cancellation.
- A managed child refused during preparation retained its parent link even though entry intent had
  never committed. The resource transaction now returns that reserved editing claim on authoritative
  terminal refusal. Entered children still require physical stop evidence. The preparation regression
  covers managed and ordinary work, and requires both lifetime holds to be released.

Both enforcement regressions were challenged in a disposable checkout. Removing inherited ceiling
checks created a forbidden nested association; bypassing public final-entry checks produced one
process entry after expiry. Both tests failed on those mutations and pass with the guards present.
Raw patches/results remain under `target/adaptive-hosts/04-review/mutation-*`.

## Compatibility and next boundary

Publication/association schema 1, run event 5, projection payload 6/envelope 2, serving hot 5/tombstone
3, managed 3, config 13, control 2.10, peer 1.5, and redb physical 15/internal 20 are exact current
contracts. Ordinary historical run events 1–4 retain their meanings; they cannot carry publication
facts. Older stores/configurations refuse instead of silently gaining new authority. Recovery,
archival and integrity scans use the same association and retained named output evidence.

05 can evaluate and promote new candidates through this publication boundary. It must preserve
accepted generations, agreements, accounts and effect protection. 06 owns live model repair,
physical second-machine and reboot/GPU qualification. Process-internal network calls are not measured
as mediated model usage. The finite verifier does not establish general application correctness or
security. These limits are not weakened by public invocation.
