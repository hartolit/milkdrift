## Result and ownership

The same Linux mechanism now prepares a Slotbook build workspace or an unrelated BusyBox text
workload through configuration. Production no longer requires a Slotbook family, writes the
application brief, assumes Rust paths or runs Git/Rust/C as protection checks. The maintained
Slotbook image contains its tools and initial brief; its ordinary worker initializer preserves
edited content. The image digest binds that content. A documentation edit alone cannot change an
approved installation.

Owned model identity is selected once in the recipe and reaches generated arguments, inference
verification and provider requests. Worker and owned-service container limits are independent,
including `/tmp`; their simultaneous memory demand is checked against observed host headroom.
Reapply/update credit only anonymous memory of the exact saved current service, because
`MemAvailable` already includes reclaimable file cache. Preparation receives that saved generation
from the semantic owner. An authorized failed preview returns `unprepared` and useful bounded
diagnostics without changing inventory or platform state.

The recipe supplies service/hash/task deadlines, explicit Vulkan layer count and the existing
provider's endpoint bounds. Unsupported workload ceilings were removed. Output admission derives
its encoded bound from the actual result serializer; combined capture enforces its bound while
reading. The protection probe has administrative limits independent of the task budget and checks
an actual denied rootfs write. BusyBox exposed why `test -w` alone was not a valid read-only test.
Systemd's finite time parser boundary is validated before it can ignore a supplied timeout.
Preparation also refuses memory/tmpfs limits that would round to a different host page boundary.
[Operating budgets](../../../../operations/managed-linux.md#choose-operating-budgets) explains the
remaining bounds and their owners, including separate authorization/admission ceilings.

The durable resource owner, use claims, exact replay, busy refusal, preserved storage, fencing,
supervisor and ID-bound cleanup remain the existing paths. There is no new provisioner, raw unit or
engine-argument interface, provider family or supervisor. Native model services were not stopped,
reconfigured or adopted.
