# What value should survive the remedial redesign?

## Current decision — G1, revision 1

Selected for this planning baseline by Rowan-20261010; not user approval or current product
semantics. Milkdrift should let people and authorized agents develop, perform, inspect, revise
and reuse methods of work, including dependable acceptance and independent tools/owners. A real
standalone Svelte interface must expose that work. The justification is the qualified
[U01–U16 source](../../../milkdrift-remedial-planning-v3/intent-source-excerpts.md), especially
U01–U04, U07–U09 and U15–U16, with origin/standing separated in
[I1](../../../milkdrift-remedial-planning-v3/working/intent-register.md).

Retain existing useful direct, managed, publication, evaluation and recovery abilities while
comparing their representations. None earns permanent retention solely from tests or an ADR.
No evidence currently justifies deleting their useful outcomes. Conversely, do not turn every
seed aspiration into a mandatory new subsystem. Release from management, generalized workflow
migration, full standards interchange and guaranteed autonomous improvement remain unresolved or
unproven additions rather than hidden obligations.

Definition, accepted history and authority remain distinct in the chosen proposal because a
user must be able to change future work and explain earlier effects without giving an agent
permission to rewrite its checks. This is reasoned retention, not unquestioning acceptance of
the present vision. Typed nodes, screen taxonomy, managed mechanism and publication setup remain
open to replacement with a complete value and transition account.

Strongest objection: preservation can keep expensive mechanisms whose current demand is uncertain.
The response is to retain compatibility and visible access during this program, while testing
their combined purpose in S21/S26/S28. A proposed retirement needs a specific user tradeoff;
the present excerpts cannot establish consent to loss. No implementation branch assumes it.

Requires explicit planning scope and I1's source distinctions. Informs P1 reuse, representation,
architecture, notation, frontend and adoption. Reopen when a concrete user journey contradicts
the value account, a source clarifies demand, or the user selects a meaningful outcome loss.
Full original conversation and real frontend use remain missing evidence.

## Purpose questions

Can a novice start useful work without learning storage/runtime vocabulary while an expert can
still inspect its true constraints? Does dependable adaptation permit useful revision of the
method itself, or merely retries? Is each preserved mechanism valuable in a real combined case,
or only in an isolated fixture? What meaningful outcome would a proposed simplification remove?
