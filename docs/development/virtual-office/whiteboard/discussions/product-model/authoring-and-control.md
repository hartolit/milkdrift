# What should an author control, and what must the execution model know?

## Current recommendation — P2, revision 2, selected for planning

Rowan-20261010 proposes intent-led compound authoring over one daemon-owned executable meaning,
retaining the current durable/authority owners while correcting demonstrated expression gaps.
Requires [G1/r1](../vision/remedial-purpose.md) and [P1/r2](reuse-service-and-placement.md).
Rowan selected this planning baseline after the actual combined review described below. It is not
user approval or an implemented product claim.

“Run both and combine results” can be one meaningful edit, while waiting and transforming data
remain distinct executable responsibilities. A generic capability task already accepts typed
inputs; making every node arbitrary instructions would move scheduling/authority into an
unvalidated interpretation. Conversely, retaining each Rust enum as a separate mandatory UI action
would preserve accidental construction burden. The daemon should accept complete semantic edits
where they eliminate duplicated multi-client construction rules; raw validated mutations remain
useful for agents and advanced clients.

There is a real expression cost: ordinary exclusive reconvergence is refused by current blueprint
validation, not an accepted graph that hangs. [E07](../../../milkdrift-remedial-planning-v3/working/observations.md)
and [standards evidence](../../../milkdrift-remedial-planning-v3/working/standards-evidence.md)
support that statement. Selected planning remedy R-C01 is a bounded same-scope choice continuation with
explicit selected-arm evidence. Its exact profile is reviewed with N1; until implemented it cannot
appear as a working ordinary merge. An explicit pinned-child alternative remains available but
adds a definition/run/context boundary that must be visible and cannot be silently inserted.

The selected contract is N1/r2, including normal arm exit distinct from run completion/quiescence,
selected data outputs without bypasses, atomic occurrence/provenance/eligibility, and compatible
future repair inside a selected arm. Existing authority, remaining allowance and unresolved physical
holds still govern entry and maintenance. The paired Branch/ExclusiveMerge form is recommended;
canonical regions remain the strongest representation alternative under the same full contract.

Strong alternatives: keep current semantics with clearer direct forms and nested choice; replace
the canonical authoring representation with structured regions; or adopt a declared executable
UML/BPMN subset. The region alternative could eliminate incomplete fork/join wiring and better
express structured choice; it owes coverage of existing cross-region data, revision adoption and
signals. Standard replacement owes exact token/data/cancel semantics and supported-data transition,
not just familiar shapes. A small diff is not a deciding argument.

Best objection: this recommendation may become a large convenience layer over an awkward core.
Reverse it if complete S06/S23/S28 authoring still requires hidden child workflows, repeated private
construction rules or an accumulating catalogue of special exceptions. A meaningful source or
countercase reopens affected decisions; dissatisfaction with names alone does not justify a rewrite.

## Purpose questions

Can a person or agent express an exclusive choice followed by shared work without inventing a
second method? Can they distinguish synchronizing branches from judging their outputs? Does a
compound action reduce required decisions or merely hide constraints until failure? What supported
graph would a region-first replacement lose, and is that loss justified?
