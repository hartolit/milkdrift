# Which notation truthfully explains executable work?

## Current decision — N1, revision 2, selected for planning

Rowan selects the reviewed activity-diagram foundation over one daemon-owned executable model,
using UML Activity conventions for task/typed data/choice/parallel/call structure, with explicit
Milkdrift annotations for exact pins, authority, bounds, outcomes and prospective adoption.
BPMN informs comparison of cross-owner communication and event handling; it is not silently
mixed into a second activation model. This selection does not claim UML/BPMN conformance or
standard interchange. It is a planning recommendation, not user approval or implementation authority.

Requires [G1/r1](../vision/remedial-purpose.md), [P1/r2](../product-model/reuse-service-and-placement.md),
the reviewed product comparison, and the owner/transport decisions as they settle. The detailed
profile is [NP2](../../../milkdrift-remedial-planning-v3/working/notation-profile.md);
[normative evidence](../../../milkdrift-remedial-planning-v3/working/standards-evidence.md) owns the
actual PDF research and source qualifications. NP2 incorporates the actual challenges below;
selection follows Bram/Cyra's actual clause rereads and Ada's affected-task recheck.

The selection adds a bounded same-scope choice-convergence remedy to the implementation program.
The [production-library probe](../../../milkdrift-remedial-planning-v3/working/merge-construction-evidence.md)
confirms that direct exclusive alternatives cannot currently converge. A paired Branch/ExclusiveMerge
is the proposed minimal executable extension, presented as one editable choice region. It forwards
only the selected route's declared results and creates no child run, new authority or parallel
branch scope. This is narrower than an unrestricted standard merge; the proposed scope, output
validation, refusal and migration obligations are explicit in the profile.

The strongest conservative alternative encapsulates the choice in a pinned child with separate
terminals, then continues in the parent. It preserves existing runtime types, but creates another
definition/run/interface/context boundary. It is useful when the author wants a reusable child;
it is not an equivalent invisible compilation for ordinary same-scope choice. A full structured
region model could avoid paired graph plumbing but needs a complete migration beyond this local
remedy. A standard executable subset remains credible if repeated gaps or actual interchange
demand justify its larger transition.

No notation/GUI task may mark an unsupported merge accepted, map Any to first success, map
Reducer First to earliest completion, present cancellation acknowledgement as stopped work, or
make a collapsed private service imply internal access. An exact diagram-to-definition contract
and keyboard/table editing are required. Interchange stays explicitly unavailable until a finite
meaning-preserving mapping and refusal contract are implemented.

Best unresolved objection: an activity vocabulary plus extensions may preserve a proprietary core
under familiar symbols, and paired choice/merge may be an awkward graph artifact. The first
connected choice/parallel/repair journey must demonstrate that an operator can predict execution.
The proposed merge remedy has received actual semantic criticism, a revised contract and focused
review of the affected tasks. Current normative readings and construction refusal
do not prove the proposed runtime behavior or usability.
