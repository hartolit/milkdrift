# gguf-backend

CPU GGUF inference and native-tokenization adapter over `llama-cpp-2`.

## Model boundary

The crate owns all llama.cpp and GGUF-specific state. It implements the portable
`domain-contracts` loader/model boundary without exposing native pointers or
vendor types. A bounded streaming GGUF header reader inspects admission metadata
without loading tensor data.

The adapter supports prompt prefill, incremental decode, and multiple logical
sequences in one llama.cpp context. Native sequence slots are allocated at
sequence creation and returned through the `LoadedModel::destroy_sequence`
lifecycle hook.

`Sha256Digest` provides GGUF content identity. A verified `GgufSource` is hashed
before and after metadata inspection and before and after native model loading,
so changed bytes at the same path fail rather than silently crossing inspection,
admission, and execution boundaries.

## Native tokenizer

`GgufTokenizer` loads a separate llama.cpp model with
`LlamaModelParams::with_vocab_only(true)` and implements the portable
`tokenization::Tokenizer` and `StreamingTokenizer` contracts. Clones share the
immutable native vocabulary and retain the SHA-256 identity of the exact GGUF
bytes loaded; construction always hashes before and after vocabulary loading.

Prompt encoding uses the lock-pinned safe llama.cpp wrapper. Because that API
always enables special-token parsing and does not expose the native switch,
`OrdinaryText` fails closed when input contains a recognized special spelling;
`Allow` and `Reject` preserve their distinct contract behavior. BOS and EOS are
validated and applied independently rather than delegated to native automatic
BOS insertion.

Decode obtains each native token piece and feeds it through request-local
incremental UTF-8 state. Borrowed and owned streaming decoders retain partial
code points across tokens and validate the final stream. Decode options can skip
control/special and end-of-generation tokens without emitting bytes.

## Safety, scope, and evidence

The self-referential native model/context owner is generated by `self_cell` in
one private lint boundary. Handwritten adapter code remains under
`deny(unsafe_code)` and exposes no native pointer.

The backend does not advertise `ALLOCATION_FREE_HOT_PATH`: the safe upstream
wrapper maintains internal vectors around decoded logits, and llama.cpp may
perform internal cache maintenance during execution.

A deterministic real 6,144-byte GGUF v3 fixture is committed at
`crates/runtime/inference-runtime/tests/fixtures/gguf-llama/tiny-llama-f32.gguf`.
Its Python-standard-library generator and the generic E0 native-backend suite
require no model download. The suite is instantiated for Candle and GGUF and
covers real load/generate, prefill/decode, greedy and seeded repeatability, EOS
and token limits, backpressure, cancellation, cleanup, unload, and shutdown.
This CPU fixture validates integration and lifecycle behavior, not language
quality, GPU execution, or allocation-free execution.

See the [GGUF backend design](../../../docs/project/gguf-backend.md) and the
[canonical fixture and test procedure](../../../docs/project/validation.md#gguf-fixture-and-shared-native-e0-suite).
